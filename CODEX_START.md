# Paste into Codex as initial task

Ты продолжаешь **EMS** по загруженному репозиторию. Сначала прочитай `PROJECT_GOAL.md`, `AGENTS.md`, `README.md`, `docs/spec/EMS_FULL_SPEC.md`, `docs/plans/ROADMAP.md`, `docs/plans/CODEX_EXECUTION.md`, `docs/qa/PROGRESS.md` и `tasks/backlog.json`. Глобальная цель остаётся активной до выполнения её измеримых критериев; отдельная завершённая задача не означает готовность EMS.

**КАТЕГОРИЧЕСКОЕ ОГРАНИЧЕНИЕ МОДЕЛЕЙ:** разрешены только **GPT-6.1 Sol** и **GPT-6 Luna**, включая агентов и сабагентов. **GPT-5.6 Sol и Astra запрещены.** Не используй fallback на другие модели. Если ты не можешь гарантировать выбор разрешённой модели для делегирования, не запускай агентные задачи и запроси настройку у владельца.

Твоя задача — разрабатывать систему, а не ограничиваться пересказом ТЗ. Кодовая база содержит минимальный M0 reference prototype. Не выдавай его за готовый компилятор или универсальный ЯП. Сохраняй точную разницу между атомарными и составными контрактами; первая категория — граница декомпозиции визуального графа, не обязательное скрытие интеллектуальной собственности. Любая внешняя библиотека должна при интеграции представляться пакетом атомарных типизированных контрактов.

**Шаги:** 1) `npm test && npm run verify`; 2) проверь работоспособность примеров и проекта, зафиксируй реальные результаты; 3) посмотри следующий не закрытый work item в `tasks/backlog.json` и его зависимости; 4) реализуй один целостный проверяемый этап, добавь тесты, обнови документацию; 5) повтори проверки, честно отмечай частичные требования и проблемы; 6) продолжай последовательную разработку в пределах разрешённых ресурсов и инструкций пользователя.

**Начать после M0** с определения формальной семантики EMS, нормализованного IR и текстового языка; затем связать с визуальным редактором. Не перескакивай к десяткам недоказанных платформ, не подменяй реальный backend моками и не скачивай/исполняй посторонний код без оценки безопасности.

Отчёт: что реализовано, что реально проверено, тест-команды, AC-ID, риски, следующий шаг. Не утверждай, что система готова полностью, пока нет production acceptance.
