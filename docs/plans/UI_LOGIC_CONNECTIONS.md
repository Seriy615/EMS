# EMS-041 — связанные UI, события и контракты

Запрос владельца: элементы конструктора, обработчики и данные должны показывать
одну программу; выбор decrement не должен оставлять delta=0 от другого выбора.
Дополнительное уточнение: вызовы контрактов на общем графе нельзя подписывать
«Переменная», а способ задания условия должен быть виден на самом блоке.

## AC-104: проверяемый срез

- Выбор UI-элемента синхронизирует конструктор, формы событий и свойств.
  Формы загружают сохранённые literal/state/event-value bindings, включая -0.
- Полноразмерный экран «Связи UI ↔ логика» строится из сохранённого проверенного
  приложения. Он показывает element/event → handler, реальные аргументы,
  возможные state.read/write и state → widget.property. Выбор открывает тот же
  элемент/свойство или исходник и граф связанного обработчика.
- Для IR2 анализ проходит только достижимые вызовы локальных контрактов от entry;
  неиспользуемый helper не создаёт ложную связь записи. Оба IR1/IR2 поддержаны.
  Это статические возможные зависимости по всем ветвям, а не история исполнения.
- Изменение аргумента проверяется существующим UIProjectEditor и Worker Runtime,
  меняет реальное поведение, сохраняется и восстанавливается при открытии.
  Неверный тип отвергается без изменения программы.
- Окна инструментов можно развернуть; основной JSON убран под раскрытие.
- На общем графе LetDeclaration с вызовом показывает контракт и типизированные
  аргументы, а имя результата — отдельную привязку. Это та же located AST/IR,
  без новой сущности алгоритма или отдельного исполнителя.
- Условия редактируются прямо на карточке, проверяются как Boolean; оба исхода
  проверены реальным исполнением. Аргументы вызовов редактируют spans того же кода.
- Пунктирные стрелки обозначают порядок выполнения; они не изображают передачу
  данных. После структурного добавления sidecar positions переносятся по точным source
  edit spans, чтобы смещённые индексы AST не наследовали координаты других
  инструкций. Полное упорядочивание вызывается явной командой «Раскладка».

Проверки: `tests/ui-connections.test.mjs`, `tests/structured-view.test.mjs`,
`tests/browser/ui-connections.test.mjs`, `tests/browser/loops-and-ports.test.mjs`,
регрессия UI/workbench, полные Node/verify/Chromium gates и публичный HTTPS smoke.

## Границы и продолжение

Экран связей — навигационное представление существующей программы. Перепривязка
события/свойства выполняется проверенной формой; рисование всех связей портами на
одном холсте и полноценный визуальный редактор всех выражений ещё нужны.
Условия сейчас принимают EMS Boolean expressions (например, sum > 4), а не весь
визуальный каталог сравнений. Зависимости opaque foreign implementations не
угадываются. Рабочее состояние Runtime не сохраняется как initial state.

После этого среза продолжать EMS-038: контрактное ядро Cell/instances/transitions/
invariants и полную визуальную проекцию на общий IR. Глобальная цель
`PROJECT_GOAL.md` остаётся активной; этот UX-срез не означает завершение языка.

## Уточнение владельца: самопроизвольное перестроение графа

Первоначальный сброс всех координат при каждом drop заменён точным переносом
sidecar positions по source edit spans. При вставке/удалении меняются AST indices,
но координаты сохраняются за прежними инструкциями. Изменение аргумента/условия
также сохраняет позиции. Камера не меняется. Новая структура располагается в точке
drop вместе со своими новыми ветвями; существующие карточки остаются на месте.
«Раскладка» — отдельная явная команда упорядочивания; «Весь граф» меняет камеру.

Бросок на пустой холст добавляет инструкцию в конец entry body перед терминальной
инструкцией, сохраняя порядок создания. Бросок на конкретную карточку вставляет
перед ней; бросок в ветвь/тело вставляет туда. Неиспользуемые helper bodies не
получают инструкции вместо выбранного entry. Поддерживаются отрицательные
координаты. Ручное произвольное переписывание исходника вне этих source edits не
является универсальной устойчивой идентификацией узлов — дальнейшая работа над
стабильными semantic IDs остаётся открытой.

Проверки: `tests/structured-layout.test.mjs` (entry/order/source-span rebase),
`tests/browser/loops-and-ports.test.mjs` (координаты, камера, порядок и explicit
arrange), native workbench и полный publication gate.
