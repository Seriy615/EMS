# Контракты управления на общем холсте

Уточнение владельца: условие и цикл представлены одной карточкой контракта,
без отдельных карточек веток, тела и AST-контейнеров. Это визуальная проекция
существующей проверенной семантики EMS, а не второй язык и не новая сущность
«алгоритм». Приоритет глобальной цели PROJECT_GOAL.md сохраняется.

- Условие: Boolean-вход, выходы выполнения «Да» и «Нет».
- While: Boolean-вход; For: вход массива и типизированный выход текущего элемента.
  Оба цикла имеют выходы выполнения «Тело» и «Готово».
- Круглые порты передают типизированные значения. Квадратные выходы управляют
  выполнением: нажать выход, затем «Выполнение» на существующем контракте.
  Операция переносится в соответствующую область того же исходного EMS.
- «+» возле выхода открывает каталог для добавления контракта в эту область;
  новый блок размещается возле выбранного контракта. Остальные позиции и камера
  сохраняются. Перетаскивание из каталога на карточку по-прежнему доступно.
- Пунктир показывает порядок исполнения. Полная последовательность отключена
  по умолчанию. При непустых ветках их стрелки начинаются у выходов контракта.
- «Выход программы» принимает итоговое значение. Добавление условия не удаляет
  существующее выражение return, его порт и передаваемые данные.
- Удаление с карточки и через контекстное меню работает в активном EMS draft,
  удаляет условие с обеими ветками либо цикл с телом. Проверка программы
  транзакционная: недопустимое удаление/перенос сохраняет исходник и позиции
  и показывает ошибку. Например, удаление единственного return из Number-контракта
  требует сначала задать другой выход. Соседние ветки не получают общую область
  переменных; запрещён перенос объявления, делающий последующие ссылки невалидными.
- Команда «Раскладка» полностью удалена. «Весь граф» меняет только камеру.

Переименование проекта открывает поле текущего проекта, сохраняет отдельной
кнопкой, поддерживает отмену и проверяется после повторного открытия. Поле
создания проекта в переименовании не участвует.

Мобильное «Вернуться на холст» закрывает окна по явному маркеру закрытия,
не нажимает кнопку разворота. Установка PWA доступна только на главной странице,
скрывается в standalone и после appinstalled, это состояние сохраняется локально.
Повторный beforeinstallprompt снимает устаревший признак установки.

## Приёмка AC-106

- Один If / While / For, ровно два выхода управления, без карточек Block.
- Присоединение существующего блока к Да/Нет действительно меняет выполнение:
  true→5, false→0; перенос в Нет даёт5 при false.
- While с подключённым телом выполняет три итерации, затем продолжение один раз:
  результат13. Типы/области видимости проверяет обычный frontend.
- Удаление поддеревьев сохраняет позиции/камеру/порты остальных блоков;
  недопустимое удаление и перенос отклоняются без потери исходника.
- Переименование сохраняется после повторного открытия; отмена не меняет имя.
- Обе мобильные кнопки возврата закрывают окна, не разворачивают их.
- Установка отсутствует в редакторах; скрывается на главной после установки и reload.
- Полные npm test, npm run verify, npm run browser:test, затем HTTPS smoke.

Проверки: structured-layout/view; browser loops-and-ports, project-manager,
mobile-pwa, ui-connections. Ряд №6, единый основной UI/logic workspace и EMS-038
остаются следующими незавершёнными срезами; эти изменения не выдают их за готовые.

## Переменные и запись

Mutable local — карточка «Переменная · имя» с редактируемым начальным значением
и обычным типизированным выходом чтения. Выход читает переменную в точке
исполнения потребителя; не добавляет реактивность к ранее вычисленным значениям.
«Записать значение» добавляет или перетаскивает контракт записи для этой переменной.
Вход «Новое значение» редактируется или соединяется с выходом другого контракта.
Его позиция в графе задаёт момент присваивания. Подключение к «Тело» повторяет
запись на каждой итерации. При новом запуске mutable local инициализируется заново;
это не постоянное состояние приложения между запусками и не завершение EMS-038.

Проверка: переменная count + контракт Сложение(count,step) + контракт Записать
в теле While(count<3) дают3 при step1; редактирование initial1 также даёт3.
Boolean в числовую запись отклоняется, предыдущая программа сохраняется.
Чтение, вычисление и запись используют существующий frontend и тот же IR.
Неизменяемый результат обычного вызова остаётся значением, а не mutable storage.
