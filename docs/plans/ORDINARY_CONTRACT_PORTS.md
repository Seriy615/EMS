# Равноправные контракты и документы проекта — AC-108/109

Уточнение владельца от 2026-10-15 заменяет прежний UX AC-106: отдельные
«Записать значение», квадратные порты и переключатель порядка выполнения
больше не являются требуемым способом работы.

## AC-108: переменная со входом

- Переменная имеет обычный круглый вход «Значение» и выход текущего значения.
  Начальное значение редактируется в свойствах. Соединение результата вычисления
  со входом переменной создаёт проверенную запись после вычисления этого результата.
- В теле цикла запись повторяется на каждой итерации. Начальное значение локальной
  переменной восстанавливается при новом вызове. UI-состояние сохраняется между
  событиями, его начальные значения восстанавливаются при перезапуске UI.
- Переподключение входа заменяет предыдущие прямые связи записи этой переменной.
  Текстовые присваивания с выражениями сохраняются как явные операции; они не удаляются
  автоматически. Прямые записи из имени выходного значения свёрнуты в связь на холсте.
- Общий обработчик соединения для данных, переменных и активации. Условие имеет
  Boolean-вход и Да/Нет; цикл Тело/Готово. Одинаковые карточки, каталог, круглые порты
  и жест выбора выхода/входа. Типы портов остаются проверяемыми.
- Нет автоматически нарисованных цепочек всех инструкций, внутренних loop-back
  линий, квадратных кнопок «Выполнение» и отдельных карточек ветвей.
- Канонические std.control.If/While/For и std.storage.Variable описаны в каталоге
  `ems-kernel-interface/1`: version, typed inputs/outputs, effects/capabilities,
  реализация intrinsic в существующем checked IR2. Это профиль интерфейсов ядра,
  а не расширение finite host Registry ABI и не eager JS-эмуляция управления.

Приёмка: runtime и standalone дают3 для count0→While(count<3)→Add(count,1)→count;
For([2,7,4])→last даёт4; переподключение5→9; Boolean→Number и невидимые значения
отвергаются без изменения программы. В браузере нет отдельной карточки записи,
координаты/камера сохраняются, обе ветви и Body/Done реально влияют на исполнение.

Границы: связь не превращает ранее вычисленный Boolean в автоматически вычисляемое
выражение на каждой итерации. Лексическая область и порядок IR2 сохраняются. Полный
Cell/instance/invariants базис EMS-038 остаётся открытым.

## AC-109: данные, свои обработчики и файлы проекта

- Существующие UI-переменные имеют редактируемое начальное значение, включая типовую
  проверку. Правка сохраняется, обновляет реальный Worker и доступна в UI-графе.
  Переименование/смена типа с миграцией ссылок здесь ещё не реализованы.
- Собственный обработчик создаётся формой имени события/контракта/необязательного
  типизированного входа. Сразу открывается обычный полноэкранный контрактный граф.
  Начальный контракт возвращает свой вход (либо0 без входов); пользователь редактирует
  его реальными контрактами. Дерево AST и исходник доступны в свёрнутых инструментах.
- Новый workspace хранит несколько проверенных документов в `ems-workspace/1`.
  Файлы UI, графы и контракты EMS открываются соответствующими существующими редакторами;
  текст и граф контракта используют тот же source/IR. Сохранение одного документа
  сохраняет последние версии соседних, экспорт/импорт и копирование включают все файлы.
- Старые проекты совместимы. «Файлы проекта» переводит старый одиночный документ
  в workspace без потери содержания. Проект и file сохраняются в URL переходов
  UI↔handler; layout/debug идентичности различают UI-файлы.
- Отказ для duplicate paths/ids, traversal, nested workspace и невалидных документов.

Приёмка: UI count initial7; создать submit(value), в обычном графе подключить
value→state.count.write→выход; привязать кнопку к submit(3), реальный Worker показывает3.
Соседний logic/Transform.ems редактируется, исполняет9+2=11 и сохраняется после открытия;
UI-файл остаётся неизменным. Негативные записи не меняют сохранённый проект.

Границы: каталог файлов — первая версия модели документов. Межфайловый импорт и
автоматическая перекомпиляция зависимых UI-контрактов ещё не реализованы; source helpers
доступны внутри модуля обработчика. Нет заявления о готовой файловой/module системе языка,
синхронизации с диском или серверного многопользовательского хранения. Следующий этап:
явные типизированные зависимости между контрактными файлами с общим линкером и атомарной
проверкой затронутых UI/графов. Глобальная цель и EMS-038 сохраняются.
