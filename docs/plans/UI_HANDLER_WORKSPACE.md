# Обычный контрактный граф внутри UI — AC-107

UI-обработчик открывается на полном рабочем холсте через «Открыть граф
контрактов» или «Открыть граф» в маршруте события. Это тот же
`installStructuredGraph` и `installCanvasNavigation`, что у программы: карточки,
типизированные порты, управление, запись в переменные, drag из библиотеки,
панели и масштаб. Прежнее техническое дерево оставлено в раскрываемой диагностике.

Холст редактирует `sources[event]` и соответствующий исполняемый handler IR
исходного `UIProjectEditor`. Сохранение идёт в тот же managed record либо локальный
UI record; не создаётся отдельная копия программы. Сигнатура события и состояние
проверяются обычным `compileUIHandler`/UI project validation. Значения параметров
приходят от UI-события; холст не показывает фиктивные редактируемые аргументы,
не влияющие на событие. При изменении исходника текущий preview закрывается.

В библиотеке доступны установленные атомарные контракты, state.*.read/write
для существующих слотов и исходные составные контракты модуля. «Новый составной
контракт» создаёт типизированное тождество value→value, явно описанное в форме;
его можно открыть, изменить обычным графом и перетащить в обработчик.
«Открыть контракт» и список контрактов переключают только представление,
сохраняя корневую точку входа UI-обработчика. Интерфейс исходной функции
получается из typecheck, не регистрируется как фиктивная atomic implementation.

Numeric +,-,*,/ показываются карточками соответствующих core arithmetic операций
с точными spans операндов. Source operator и IR сохраняются. Никакого превращения
ленивых &&/|| в eager atoms. Невынесенные вложенные выражения остаются выражениями
на входах; полного автоматического разложения всех выражений этот срез не обещает.

«Запустить UI» создаёт настоящий UI Worker и показывает приложение: нажатие его
элемента вызывает сохранённый обработчик. Возврат в конструктор открывает тот же
проект и изменённый источник. Открытие без source witness явно отклоняется:
atomic handler не превращается в выдуманный редактируемый граф.

Сохранение на стороне холста сравнивает исходную сохранённую версию с текущей;
изменение из другой вкладки даёт STALE_UI_PROJECT и сохраняет обе версии. Это
не универсальный механизм слияния или гарантия против перезаписи из старого
UI-конструктора. Эту границу сохранять до общего project revision protocol.

## Приёмка

- Мобильный полноэкранный viewport390px, общие карточки/порты.
- Изменение аргумента счётчика delta*4 → настоящий UI показывает4.
- Создать user.Transform, собрать Сложение(value,2), подключить к его результату.
- Перетащить helper в корневой граф, соединить delta→helper→Сложение/state.write.
  Нажатие UI даёт3; повторное открытие конструктора также даёт3.
- Managed UI: конкурентное изменение source даёт STALE_UI_PROJECT;
  поздняя правка холста не перезаписывает чужую версию, project id сохраняется.
- Регрессия прежних authoring/debug paths, полный gate и публичный HTTPS proof.

Далее — упрощение общего конструктора событий/состояния и UI layout, задача
ряда №6 и EMS-038. Глобальная цель PROJECT_GOAL.md не объявляется достигнутой.
