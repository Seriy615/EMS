# EMS-042 / AC-105 — один граф с типизированными портами

Запрос владельца: добавление условия/цикла не должно убирать входы/выходы,
переставлять прежние контракты или изображать их все соединёнными с новым блоком.
Обязательная форма создания цикла с текстовым условием отменена.

## Проверяемые критерии

- Параметры entry, значения локальных привязок, аргументы вызовов и результат
  программы видны как типизированные порты. У If/While есть Boolean-вход условия,
  у For — вход массива и выход текущего элемента с выведенным типом.
- Соединение заменяет соответствующий expression span в том же EMS source;
  обычный frontend проверяет типы, область видимости, эффекты и IR. Дополнительно
  сверяется точная lexical binding identity: одноимённое значение из другой
  ветви не подменяет выбранный выход. Неуспех сохраняет прежнюю программу.
- Сплошные линии данных рисуются только для настоящих прямых NameExpression
  bindings. Литералы и вложенные выражения не превращаются в выдуманные связи.
  Вложенные выражения остаются редактируемыми текстом до дальнейшей декомпозиции.
- If/loop не получает связи данных при создании. Порядок выполнения обычных
  инструкций скрыт по умолчанию и включается отдельно. Подписанные переходы
  ветвления/итерации остаются видны как управление, а не как данные.
- Переход от обычного графа к графу с управляющими конструкциями переносит
  native positions по параметрам, именам значений и result; камера не меняется.
  Последующие вставки используют source-span position rebase.
- Цикл создаётся сразу в точке drop. While получает явно отображённое условие
  false («Нет»), For — пустой типизированный массив через обычный
  std.value.NumberArray([]). Это безопасные начальные значения входов, а не
  незаметные демонстрационные операции. Тело пустое. Клавиатура не вызывается.
  Поле исходного выражения доступно дополнительно в свойствах блока.
- Подключение Boolean к циклу, изменение тела и реальное завершение проверены:
  mutable flag=true, тело count=count+1; flag=false → результат1.
- Исходный граф a=2,b=3 →sum сохраняет три связи и позиции после If; новый If
  не получает data edge. Переподключение b→sum.a даёт6 вместо5.

## Семантические границы

Чтение mutable binding в условии выполняется при каждой проверке по обычной
семантике EMS. Результат ранее исполненного неизменяемого сравнения остаётся
значением; подключение выхода не обещает повторного исполнения производителя.
Граф не вводит скрытой реактивности или нового интерпретатора. Полная визуальная
декомпозиция всех выражений/ветвей, перенос источников внутрь predicate region,
удаление связей жестом, layout export и единый canvas всех UI-handler операций
остаются дальнейшей работой. Изменение привязки сейчас выполняется портом или
редактированием соответствующего аргумента/выражения.

Доказательства: `tests/structured-ports.test.mjs`,
`tests/browser/loops-and-ports.test.mjs`, native/workbench integration, полный
Node/verify/Chromium gate и проверка опубликованного сайта. Глобальная цель и
EMS-038 Cell/instances/transitions/invariants не объявляются завершёнными.
