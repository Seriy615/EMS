# ADR-0016: текст графа является телом контракта

Статус: принят в описанном профиле, AC-132. Цель — G-01/02/03 и полноценный общий язык;
остальные критерии PROJECT_GOAL.md остаются обязательными.

Печать compiler-generated pc/while автомата полезна для экспорта текущего IR,
но не даёт обратной связи с авторскими узлами: новый parse создаёт другой
низкоуровневый граф, теряя ID, edges и metadata. Использовать sourceArchive как
текущую программу или подкладывать устаревший bodyGraph недопустимо.

Решение: `@Name(...) -> Type graph { ... }` — дополнительная форма тела того же
EMS-контракта. Parser и система типов общие; семантический граф использует
прежние профили и валидатор. Правило lowering извлечено из рабочего compiler,
без второго evaluator. Source forward signatures — временные интерфейсы
настоящих функций, их bodies/effects проверяются общим checker; executable
registry не получает заглушек.

В обычном canvas сохраняются именно semantic node/contract IDs, а geometry,
описания и тестовые входы остаются отдельными metadata. Текстовый черновик
отделён от проверенной программы и защищён CAS; Apply не переставляет старые
узлы и не придумывает активации. В native/UI scope остаётся единый whole-module
Save с прежними guards, state ownership и workspace CAS.

Следствия: графовые тела естественно компонуются с обычными контрактами в языке,
а строго графовый документ хранит только инспектируемые графовые реализации.
Неподдерживаемое смешанное представление не должно молча превращаться в FSM.
Полный native source-document inverse, исходная native projection с авторскими
node IDs, static structure authoring и межфайловое linking остаются следующими
архитектурными зависимостями, а не считаются закрытыми этим ADR.
