# Журнал запуска и местоположение ошибки графа

`executeGraph(...,{onNodeFailure})` допускает optional observer `(callPath)=>void`. При ошибке actual atomic/composite operation или проверки её результата observer получает скопированный путь `{graph,node,contract}` от внешнего графа до текущей операции. При nested failure первое сообщение содержит точный leaf/caller chain; последующие parent сообщения могут быть короче. Ошибки вычисления аргументов принадлежат реально упавшему producer. Валидация до операции не придумывает node location.

Observer не изменяет `error.code`, `error.details`, порядок вычисления или результат. Observer exception игнорируется. Invalid non-function option отвергается. Путь не содержит аргументов, состояния, результата, ключей или native implementation. Прежние runtime/compiler conformance error vectors сохраняются.

Studio Worker сохраняет первый failure path отдельным диагностическим полем транспорта, client переносит его отдельно от semantic error details. Графовый редактор выделяет соответствующий node текущего workspace; для ошибки вложенного контракта это его call block, при исполнении раскрытого body — leaf. Полный автоматический переход в вложенный failing graph и source-map/control debugger ещё открыт.

`#execution-log` показывает actual Worker request start, успешную проверку сохранённого проекта, terminal completion/failure/cancel/deadline. «Проект проверен» относится к stored project, не утверждает проверку необработанного text candidate: текст проверяется ordinary frontend при Run. Лог не имитирует пошаговую трассу. UI событийная trace остаётся собственностью existing ReactorKernel. Путь и lifecycle — authoring diagnostics, не новое semantic IR.


## Настоящее пошаговое исполнение графа вызовов

`executeGraph(...,{onNodeEnter})` принимает optional async callback для паузы **перед actual operation**, после вычисления зависимостей и проверки policy. Event содержит только `phase: "enter"`, `callPath`, `frames`, имена/типы `inputs`, тип `output`, названия `effects`/`capabilities`. Значения входов, результатов, state, error payloads и реализации не передаются. Metadata отделена копированием; изменение event не изменяет программу. Отсутствие observer сохраняет прежнее исполнение; exception/rejection observer игнорируется, AbortSignal отменяет даже неразрешённую pause promise. Trusted observers могут задержать исполнение; это диагностический интерфейс, не sandbox. Observer не служит обработчиком semantic exceptions.

Пауза следует actual demand-driven порядку: зависимости раньше consumer, memoized producer останавливается один раз, dead nodes не запускаются. Composite сначала останавливается на своей границе, затем на реальных внутренних operations с полным caller path. Atomic implementation не раскрывается. Ошибки до начала operation не создают фиктивную паузу. Standalone compiler пока не экспортирует debug hooks; числовая семантика остаётся общей.

`GraphStepper` управляет тем же evaluator. Каждый pause получает новый token. Только совпадающий token и `step`/`continue` освобождают текущую паузу; устаревшие/повторные/неизвестные команды отвергаются. Step разрешает одну operation до следующей entry; Continue отключает последующие паузы. История значений не собирается. Studio Worker принимает отдельные resume сообщения, пока ordinary execution ожидает gate; Worker termination завершает Stop/deadline. Client предоставляет `onPause` и `job.resume(mode)`; команды после terminal result не отправляются.

IDE: «Отладка» → путь/типы текущей operation → «Шаг» / «Продолжить» / «Остановить». Работает снимок проекта, переданный Worker при старте; изменения редактора не меняют этот запуск. При совпадении текущего workspace выделяется соответствующий caller block. Nested leaf path виден в панели, но автоматическое раскрытие вложенного body ещё не реализовано. Обычный Run имеет прежний 5s deadline, интерактивный debug — общий 60s deadline, включая паузы.

Область первой реализации: чистые call/dataflow графы, вложенные composites и явный порядок sequence существующего профиля. AC-065 первоначально не включала text/control IR, Map/Filter/control callbacks, UI state/event handlers и native/foreign debug. Текущая text/control реализация описана в AC-066 ниже; visual collection graph debug по-прежнему получает `UNSUPPORTED_DEBUG_PROFILE`, ordinary Run доступен. Full EMS-033 и AC-012 не закрыты. Доказательства: `tests/graph-debugger.test.mjs`, `tests/browser/graph-debugger.test.mjs`, verify check.


## Control IR и текстовое соответствие — AC-066

`executeControlIR(...,{onControlEnter})` — async диагностическая точка перед исполнением actual statement/expression, после ordinary tick/cancellation/budget checks. Event: `phase: "enter"`, `profile: "control"`, `function`, структурный `node` address, `kind`, `type` (или null), `callStack` функций, `frames` и текущий счётчик `step`. `step` — существующий semantic budget counter, а не новая нумерация языка; служебные loop/invoke ticks могут создавать промежутки. Значения literal/locals/arguments/results/state/resource/future payloads не передаются. Array caller stack отделён копированием. Exception/rejection observer не изменяет semantic error; отмена завершает неразрешённую pause promise и сохраняет protected cancellation/finalization/resource cleanup.

`controlNodeEntries(fn)` определяет структурный JSON-pointer address относительно тела конкретной функции, например `/body/0/condition/left`. Lowering сохраняет реальные AST ranges в `ems-provenance/1.functions[functionId].nodes[address]`. Specializations получают собственные карты и actual function IDs. Координаты не добавляются в IR; serialize/parse/compiler/witness сохраняют прежний semantic artifact. Source-only whitespace/comments меняют sidecar, но не IR. Эти addresses относятся к конкретному IR snapshot, а не к стабильным ID после правки программы.

`runTextDraft(draft,editor,inputs,options)` создаёт свежий checked bundle с sidecar, исполняет прежний IR и добавляет `location` к diagnostic event из этого же bundle. Call IR использует прежнюю карту graph/node, control IR — function/address; неизвестное соответствие возвращает null. Пользователь не передаёт произвольную map для выполнения. Copy location не меняет sidecar/программу. Прежние maxSteps10000/maxDepth32 и effect/capability preflight текста сохраняются.

«Отладка» в text mode использует тот же Worker, Step/Continue/Stop и60s total deadline. Панель показывает actual function chain, operation address/kind/type и строку/столбец. Выделение текста использует UTF-16 offsets parser/textarea и выполняется только если текущий editor source совпадает с переданным снимком. Правка текста во время паузы сохраняет запуск снимка и исключает неверное выделение новой версии.

Составные вызовы и ленивые branches/loops исполняются обычным runtime; невыполненные ветки не создают trace. Generic lowering, exceptions, async local functions/futures, resource operations сохраняют существующие profiles. GraphStepper теперь ставит конкурентные entries в FIFO очередь: видна одна pause, token шага освобождает текущую, Continue освобождает также накопленные entries. Очередь не обещает deterministic ordering внешних futures; никакой второй scheduler/evaluator не вводится. Worker termination по-прежнему ограничивает незавершённые browser tasks.

Проверки: semantic IR roundtrip/comment shift, real pause/selected branch/loop repeats/nested function locations и compiled result; observer mutation/rejection, protected cancellation/step limits, resource cleanup после отмены в паузе, queued futures, call IR provenance; actual Chromium source selection (включая Unicode comment), nested Step/Continue6, stale edited source guard, Stop/recovery. Полный UI event/state debugger, visual collection stepping, breakpoint/Step Over/native/compiled debugging и полный AC-012 остаются открытыми. Карта координат сама по себе не доказывает полноту visual round-trip.


## UI события и подтверждённое состояние — AC-067

ReactorKernel dispatch принимает optional `onControlEnter`/`onNodeEnter`/`onFrameExit` alongside AbortSignal; callbacks проверяются до enqueue и передаются прежнему linked handler executor. Queue order, grants, copied input payload, private draft, commit/rollback/cleanup остаются собственностью того же kernel. Пауза после state write не публикует draft: snapshot/view остаются последними подтверждёнными значениями. AbortSignal прерывает actual diagnostic await, откатывает событие и сохраняет FIFO; observer не получает draft/state values.

`createUIWorkerRuntime(project,{debug:true,onPause,onDebugEnd})` создаёт обычный persistent preview с диагностическим транспортом. При init Worker проверяет весь typed project, version closure и source→IR witnesses; fresh compiled source maps существуют отдельно от runtime application. В dispatch gate создаётся для конкретного transport event ID, token принадлежит этой gate. Client `resume("step"|"continue")` отправляет event ID/token; stale ID/token/неизвестный mode не освобождает чужую транзакцию. Continue относится к текущему событию, следующее FIFO event снова останавливается. Конкурентные функции внутри одного handler используют очередь существующего GraphStepper.

Pause transport содержит только ordinary graph/control metadata + `handler`, `location`, `token`; client добавляет `eventId`. Private draft, state/result/argument values отсутствуют. Состав полей проверяется, callback получает copy. Optional onDebugEnd сообщает eventId/ok/error code после terminal dispatch (не init). Legacy/source-less handlers исполняются и останавливаются по actual IR; source location null явно означает отсутствие карты. Карты не принимаются от пользователя без source witness verification.

Deadline/Stop client по-прежнему прекращает **весь Worker preview**, отклоняя активные и ожидающие события; остаются только acknowledged snapshot/view. Host side effects не получают обещания rollback или cleanup после forced termination — reference preview содержит trusted built-in finite bindings, не sandbox произвольных plugins. Обычный deadline5s сохранён; IDE debug preview использует60s на event request, включая очередь/паузы.

UI: «Отладка событий (новый запуск)» создаёт новый preview с initial state; затем actual control нажатие/ввод создаёт событие. «Шаг»/«Продолжить событие» управляют gate, terminal panel сообщает commit/rejection. «Остановить отладку» сохраняет отображаемое confirmed состояние и закрывает Worker. «Начать заново» возвращает обычный preview. Исходник выделяется только для открытого того же handler и совпадающего authored snapshot; editor inputs остаются отзывчивыми.

Acceptance: real Worker FIFO0→1→2/unique event IDs, unknown/stale resumes, source mismatch before init, missing grants, invalid callbacks before enqueue, pause deadline and Stop; actual write to draft followed by return pause, confirmed1 remains1 after termination; direct local AbortSignal rolls back same draft and marks cancelled trace. Actual Chromium source selection/Step/Continue commit1, second event paused after draft write but snapshot1, Stop/CANCELLED/ordinary restart1. Полные debugger breakpoints/Step Over/value redaction classification, compiled/native debugging и whole visual parity остаются открытыми; глобальная цель не закрывается AC-067.

## Operation breakpoints (AC-069)

`GraphStepper(onPause, {start: 'step' | 'continue', breakpoints})` использует исходные runtime enter hooks. Step останавливается перед следующей фактической операцией. Continue выполняет операции до точного совпадения точки; повторный Continue снова останавливается на той же операции при следующей итерации или вызове. Невызванная функция, неиспользуемый demand-узел и ленивая невыбранная ветка не создают остановок. Остановка composite-узла совпадает с последним элементом callPath, а не с каждым потомком в его caller path.

Точки — максимум64 уникальных записей, каждый адрес ограничен1024 UTF-16 units, разрешены только три поля:

- `{profile: 'graph', graph, node}` — точный ID графа и операции;
- `{profile: 'control', function, node}` — ID функции и структурный путь `/body/...` из свежего provenance.

Дубликаты удаляются, неизвестные профили/поля и значения вместо метаданных отвергаются `INVALID_DEBUG_BREAKPOINT`. Gate options разрешают только `start` и `breakpoints`; ошибочная конфигурация — `INVALID_DEBUG_OPTION`. Неисполняемый или отсутствующий адрес не совпадает ни с одной операцией. Верификация типов/эффектов/permissions по-прежнему выполняется до enter hooks; breakpoint не предоставляет capabilities.

`update(token, points)` меняет политику только текущей паузы, копирует входной список и не освобождает выполнение. Старый токен не меняет gate. Continue пересматривает queued concurrent entries: совпадающие остаются остановками, остальные освобождаются в существующей очереди; дополнительного evaluator/scheduler не создаётся. Cancellation и hard Worker deadline остаются прежними.

Studio Worker принимает начальные `debugOptions` только для debug execution и отдельное `{type:'debug-breakpoints', token, breakpoints}` во время паузы. Некорректная live update игнорируется, старая валидная политика сохраняется. Клиент `setBreakpoints` валидирует список до transport; Step/Continue token protocol и pause metadata не меняются.

В IDE графовая точка добавляется в свойствах выбранной операции и отмечается красной точкой. В тексте «Точка под курсором» компилирует текущий typed source и выбирает минимальный provenance range, содержащий cursor offset; комментарий/пробел вне executable range — `NO_DEBUG_LOCATION`. Литерал также является исполняемой операцией control IR. Раздел «Точки останова» позволяет идти сразу до точки, поставить её на текущей паузе и удалить все точки без освобождения текущего исполнения.

Точки эфемерны: не входят в IR, canvas, exported code или saved project. Их identity включает проект, semantic graph/library и точный текст/entry/lowering. Изменение программы или переключение профиля сбрасывает точки; переименование, viewport и input values не меняют operation identity. Уже исполняющийся Worker продолжает собственный снимок; после правки IDE не применяет новые точки к старому снимку. Full persistent source anchors, UI event breakpoint authoring, Step Over/Out, native/compiled debug transport и value-policy debugger остаются отдельными незавершёнными требованиями.

Evidence: `tests/breakpoints.test.mjs`, `tests/browser/breakpoints.test.mjs`, `tools/verify.mjs`, live case в `tools/deploy-smoke.mjs`.

## Activation-aware Step Over/Out (AC-070)

Control enter events и graph enter events теперь имеют `frames`: execution-local массив уникальных положительных ID (root → текущий activation). IDs выделяются исходными evaluator, а не IDE и не именем функции. В одном control execution вызовы функций, рекурсия, async siblings и вложенные composite graphs используют общий allocator. Graph frame — вызов графа, control frame — вызов функции. Async call сохраняет ancestry вызывающего кадра, но получает собственный ID. Имена в `callStack`/`callPath` остаются для отображения. ID не содержит runtime values, не входит в IR/provenance/compiled artifact и не является глобальным ID другого запуска или UI-события.

Опциональный `onFrameExit({frames})` сообщает выход реального кадра после выполнения/ошибки и cleanup его block. Callback синхронно вызывается с копией ID; возвращённый Promise не ожидается, его rejection и синхронное исключение игнорируются. Этот hook не заменяет semantic error и не задерживает программу ожиданием Promise наблюдателя. Preflight проверяет callable option; resources/futures session completion и UI commit остаются ответственностью существующих runtime kernels. Выход root функции может предшествовать join её futures и session cleanup; success определяется terminal result, не exit notification.

`GraphStepper.resume(token, 'over' | 'out')` требует корректного `frames` текущей паузы (1..64 уникальных positive safe integers). Без реального activation metadata возвращает false и сохраняет паузу, без догадок по stack depth. `leave(event)` подключается к `onFrameExit` и сообщает завершение выбранного кадра.

- Over выполняет текущую control statement/expression целиком, пропуская её структурные потомки и вложенные activations. Следующая операция того же кадра останавливается; повторное исполнение того же адреса в цикле является новой операцией. Для graph node Over пропускает вложенный composite graph. Если кадр завершился, следующая фактическая операция его предка может стать остановкой.
- Out выполняет выбранный frame до его выхода и останавливается перед следующей фактической операцией живого предка. Out root приводит к обычному завершению программы/события, либо к совпавшей явной точке.
- Явные breakpoints имеют приоритет над Over/Out. Новый resume после такой остановки выбирает новый stepping plan. Старый токен не меняет план или выполнение.

Другой async sibling не является текущим кадром даже при том же function name/depth. Операции предка, начавшиеся до exit выбранного async frame, не считаются возвращением: они продолжаются по исходной future семантике, чтобы debugger не блокировал необходимый producer. Если после exit уже нет новых ancestor enter events, execution нормально завершается. Это operation stepping, не stop-the-world scheduler и не эмуляция обратного входа в уже выполненную строку.

Studio и UI worker transport разрешают modes step/continue/over/out с прежними request ID/token checks. UI pause whitelist включает frames и проверяет bounded/unique IDs до callback; остальные поля и запрет value payload прежние. ReactorKernel передаёт exit hook в исходный event execution, без изменения private state draft/FIFO/commit/rollback. Кнопки «Через операцию» и «Из функции» доступны только на паузе; UI stop/deadline сохраняют последнее подтверждённое состояние.

`tests/step-frames.test.mjs` и `tests/browser/step-frames.test.mjs` проверяют nested/recursive/async/mixed graph-control frames, breakpoint interruption, canonical IR/compiled parity, cancellation/resource cleanup, actual DOM buttons/source selection/UI commit/Stop. `tools/verify.mjs` и `tools/deploy-smoke.mjs` включают Over/Out→7 и UI Over/Out→commit1. Full UI breakpoint authoring/persistent anchors/native/compiled debugging/value policy остаются открытыми.

## Source-owned UI event breakpoints (AC-071)

UI debug options разрешены только при debug:true: `{start:'step'|'continue',breakpoints:[{handler,point}],sources:{handler:{source,entry}}}`. Operation point имеет прежнюю graph/control форму AC-069. Список ограничен64 записями; witness передаётся один раз для каждого referenced handler, orphan witnesses запрещены. Source budget262144 UTF-8 bytes на handler/1048576 aggregate, entry/handler bounded1024. Records допускают только указанные поля; invalid options/payload/limit отвергаются до создания Worker в клиенте. Debug policy не входит в IR, saved project или export.

Worker сначала проверяет существующий UI source→IR witness, затем компилирует свежие provenance bundles. Каждый breakpoint требует точного source+entry равенства running handler (`STALE_DEBUG_SOURCE` при несовпадении, даже при IR-equivalent комментарии), правильного profile и реального адреса в provenance (`INVALID_DEBUG_BREAKPOINT`). Значения state/inputs не входят в pause transport. Capability policy/FIFO/draft/commit/rollback остаются прежними.

`setDebugOptions(options)` разрешён только на текущей паузе. Transport `{action:'debug-policy',id,token,options}` не освобождает её: host применяет policy только при exact current event ID/token и checked witness. Invalid/stale commands игнорируются, прежняя policy сохраняется. Gate следующего queued event создаётся лениво на первом actual enter, поэтому уже стоящее в FIFO событие получает новую policy после предыдущего commit. Continue снова останавливается на совпадении; Out/Over и explicit point priority прежние. Закрытие Worker на приватной записи сохраняет последний ack snapshot.

IDE позволяет выбрать cursor operation в применённом handler source, выбрать source-graph region и поставить точку либо запомнить текущую остановку. Графовая точка выводится из исходного range через тот же fresh typed provenance, не из координат SVG. Неприменённый source/entry и устаревший граф отвергаются. Точки эфемерны и связаны с exact application/source identity; изменение приложения сбрасывает их. Добавление точки в idle preview не перезапускает приложение/не сбрасывает state: статус сообщает, что policy начнёт действовать при новом запуске отладки. На текущей matching паузе она применяется сразу; start mode влияет на следующие event gates.

Evidence: `tests/ui-breakpoints.test.mjs`, `tests/browser/ui-breakpoints.test.mjs`, `tools/verify.mjs`, public smoke UI private0→point→commit1/private1→live clear→commit2→next event3. Persistent source anchors, secret/value inspection policy, native/compiled debug transport и full IDE parity остаются открытыми.


## AC-072 — проверяемые source anchors

`src/studio/source-anchors.mjs` создаёт отдельный сериализуемый sidecar `ems-source-breakpoint/1`: исходный typed point и canonical identity. Capture и resolve работают только с bundle обычного проверяющего frontend и его свежим provenance; compiler, runtime, EMS IR и canvas не получают anchor metadata. Это идентичность операции в программе, а не обещание неизменных значений или поведения после любых edits.

Для control IR identity включает signature/policy текущей функции, typed subtree операции, роль expression/argument, enclosing control headers/branch и предшествующие lexical let/using declarations. Statement array indices исключены: вставка соседнего оператора сдвигает адрес, но может сохранять identity. Новая декларация в контексте консервативно снимает привязку даже при потенциально безопасном изменении; состояние анализа данных не имитируется. Изменения operation/operator/literal/binding initializer/branch condition/function signature снимают привязку. Дубли одинаковой identity при создании отклоняются, при перепривязке дают `ambiguous`; старый адрес не имеет приоритета.

Для call IR identity содержит graph signature и typed contract ID/version/interface/policy, arguments и рекурсивные semantic dependency signatures без сгенерированных node IDs. Explicit sequence учитывает предшествующие операции, поэтому изменение последовательности может консервативно снять привязку. Изменение dependency снимает привязку. Source helper implementations за стабильной typed call boundary могут меняться; anchor не заменяет проверку версии библиотеки или доказательство эквивалентности.

Resolve возвращает свежий exact point только при одном совпадении в том же graph/function/profile; иначе `point:null` и `ambiguous` либо `changed-or-missing`. Невалидный draft также деактивирует точку. IDE показывает непривязанные точки, хранит их для восстановления/Undo и передаёт Worker только разрешённые свежие points вместе с прежним exact source witness. Изменение текста на паузе не подменяет выполняющийся снимок программы. Payload-free pause/ID/token, grants, FIFO/private draft/commit/rollback и deadline сохранены.

UI anchors хранятся отдельно в localStorage (`ems.ui-source-breakpoints.v1:<managed-or-local>:<application-id>`), максимум64 записи и1 MiB UTF-8 на документ; capture identity ≤1 MiB, временный индекс ≤8 MiB/20000 locations. Metadata может содержать исходные литералы программы, но не runtime values; это локальные данные редактора. Ошибка quota сохраняет прежний набор точек и текущую policy. Повреждённые записи отклоняются без автоматической перезаписи. Project exports/standalone packages не содержат sidecar. Открытие UI проекта заново перепроверяет сохранённые anchors на его текущем источнике.

Studio text anchors переживают safe edits и промежуточный invalid draft в текущем workspace. Их durable storage и перенос при смене режима/entry/library пока открыты; UI persistence не объявляется полной persistent IDE parity. Generic specialization IDs могут консервативно измениться при relowering. Native/compiled debugger и безопасная политика inspection runtime values также открыты.


## AC-073 — durable Studio debugger sidecar

`src/studio/debugger-storage.mjs` хранит `ems-studio-debugger/1` отдельно от portable program: project owner и до64 записей `{context,point,anchor}` в `ems.studio.debugger.v1:<project-id>`. Один документ ≤1 MiB UTF-8; schema/version/owner/exact fields, point profile, source anchor agreement и duplicate records проверяются до записи. Quota/validation failure не меняют bytes, активный набор или pause token. Read corruption отклоняется без автоматической перезаписи; очистка — явное действие пользователя.

Context содержит mode, а для text — entry/lowering. Library identity включает semantic graphs/collections и sorted registry binding ID/version/kind/typed inputs/output/effects/capabilities/interface boundary. Canvas, display names и runtime inputs исключены. Restore не вызывает foreign/atomic callbacks. Это консервативная exact metadata identity, не доказательство эквивалентности callback implementation и не замена pinned library validation.

Graph records активны только при exact текущей library identity и существующем graph/node. Source records повторно разрешаются через проверенный frontend bundle и AC-072 anchor; invalid draft остаётся inactive. Library drift помечается `library-changed`; изменённые graph/source операции не переадресуются на ближайший старый node. Mode/entry/lowering переключение сохраняет остальные contexts. Undo library/source может вернуть point. Кнопка «Убрать все точки проекта» очищает все contexts этого project owner и обновляет active paused policy только после успешного storage write; сама пауза не освобождается.

При смене проекта draft загружается перед восстановлением points. Program/IR/project/standalone exports не содержат debugger sidecar. Catalog copy/import и legacy Studio file import получают новые project identities, поэтому не наследуют локальные points; file import теперь всегда создаёт copy, даже если ID из файла отсутствует в каталоге. Старые project/sidecar records не удаляются. UI sidecar AC-072 сохраняет прежний формат и поведение.

Durability покрывает local graph/text Studio и source-owned UI. Cross-tab conflict/synchronization, collaborative debug state, native/compiled transports и typed runtime value/secret inspection остаются открытыми. Выполняющийся Worker всегда продолжает прежний checked snapshot: source/library edit не подменяет его IR и не передаёт ему points другого snapshot.


## AC-074 — core typed inspection API

`executeControlIR`/control `executeIR` принимают optional `inspection` только вместе с `onControlEnter`. Policy: `{allow:[{function,names}],protectedFunctions?,maxBytes?,maxStringBytes?,maxArrayItems?}`. Defaults allow/protectedFunctions empty, maxBytes8192 (256..65536), maxStringBytes4096 (0..16384 UTF-8), maxArrayItems128 (0..1024). ≤32 function grants/32 binding slots total, ≤64 protected functions. Все поля exact и own data properties; inherited option/grants не активируют inspection, object/array accessors и sparse/extra array metadata отвергаются без getter invocation. IDs bounded, duplicate/unknown/ambiguous binding/functions отклоняются до callbacks. Policy копируется при старте и не изменяется live через caller object.

Opt-in event дополняется `inspection:{schemaVersion:'ems-inspection/1',variables:[{name,type,status,value?}],truncated}`. Frame identity, function/address и scope — реальная текущая activation. Parameters/let/using/catch/for/for-await/pattern binding types идут из IR, не из guessed JS type. До declaration статус `not-in-scope`. Snapshot statuses: `value`, `not-in-scope`, `protected-program`, `protected-effects`, `excluded-type`, `limit`, `unavailable`. Whole snapshot ≤maxBytes UTF-8 JSON; exceeding next record даёт truncated=true без partial value. Observer mutation/throw не подменяют execution result/error; returned arrays/algebraic payloads detached, signed zero сохранён.

Supported finite values — Number/Boolean/String/NumberArray и nested Option/Result. Future/Stream/ResourceHandle в любой позиции type исключаются до чтения cell.value. Accessor fields не вызываются; слишком большие strings/arrays не возвращают prefixes. Fn.policy effects/capabilities либо localEffects закрывают projection, даже при granted execution. Host-marked protected function закрывает values всей программы до любого чтения snapshot; это консервативный barrier для secret-derived values, не автоматическая secret inference/taint или declassification. Host обязан правильно классифицировать данные: явно разрешённый немаркированный String не гарантированно публичный.

Без policy event остаётся payload-free. IR/serialized project/standalone compiler не получают inspection metadata. Mixed control→graph executes normally, graph portion stays payload-free; explicit direct graph value inspection →UNSUPPORTED_INSPECTION_PROFILE. Studio Worker inspection request →UNSUPPORTED_INSPECTION_TRANSPORT до исполнения. Поэтому IDE value panel пока отсутствует; существующий Step/Over/Out/FIFO/commit/rollback не получает новые values. ADR0014 определяет trust boundary/limits и следующий checked Worker/IDE этап.

## AC-076: checked Studio inspection и панель

`startStudioExecution` поддерживает `inspection` только для `action:"text",debug:true` и control IR2. Собственное data-поле содержит `{schemaVersion:"ems-source-inspection/1",source,entry,lowering,policy}`; источник, точка входа и профиль точно совпадают с draft. Клиент и Worker независимо восстанавливают typed bundle из переданного проекта и проверяют policy до исполнения. Неизвестные/неоднозначные имена и неподдерживаемые профили отвергаются. Изменения основной программы/библиотеки в IDE снимают разрешения; редактирование во время активного просмотра отменяет запуск.

Оба конца транспорта проверяют замкнутый DTO паузы: адрес/вид/тип операции, источник, стек функций, уникальные положительные frame IDs, положительный token/step, разрешённые имена, объявленные типы, статусы, конечные payloads и бюджеты. Клиент отвергает повторный/перекрывающийся token до callback, завершает Worker и возвращает общий `INVALID_INSPECTION_SNAPSHOT` без payload. Неразрешённые собственные inspection-поля в обычной паузе также отвергаются. Графовые кадры внутри control→composite сохраняют прежнюю отладку и проходят проверку metadata без inspection.

В нижнем разделе «Просмотр переменных — по разрешению» выберите переменные текущего кода, затем начните отладку. По умолчанию ничего не выбирается и значения не передаются. Разрешено не более32 имён; неоднозначные имена недоступны до будущих scope-address grants. Значения очищаются при Continue/Step/Over/Out, Stop, завершении, изменении программы и повторном открытии. Разрешения и снимки не записываются в localStorage/проект/экспорт. Поля выбора блокируются на время такого запуска. Строки отображаются через textContent.

Флажок защищённых данных маркирует весь program barrier через entry; в снимке остаются только статусы. Это явная классификация владельца, а не автоматическое распознавание секретов. Доверенный runtime производит фактическое значение: DTO validation проверяет форму и разрешение, но не доказывает истинность значения от скомпрометированного Worker. M0 доверенный JS не является sandbox. Обычные выходы программы не редактируются инспектором. Effectful UI state/native/compiled profiles и формальный taint остаются отдельными задачами.

## AC-077: QA Worker startup evidence

`tools/lib/chromium.mjs` устанавливает пробу только в локально запускаемом QA-браузере. Для Worker сохраняются последовательный ID, безопасный module path, state, время создания/последнего события, число попыток postMessage и полученных message events. Ошибка содержит только наличие message, безопасное filename, integer line/column и признак после terminate. Payloads, raw error text, request headers, query/fragment и внешние origins не сохраняются. Records ограничены64, errors16, CDP metadata128; возвращаемые server/network snapshots detached. `page.diagnostics()` доступен тестовому процессу, не странице EMS через HTTP.

AutoAttach выполняется с waitForDebuggerOnStart:false; Worker не приостанавливается, не перезапускается и таймауты не продлеваются. Первые entry requests могут завершиться до CDP Network.enable. `startStudioServer({recordModules:true})` дополняет доказательство реальными HTTP finish/close событиями:128 recent,16 failed/incomplete, без тела/headers/query. Default false; публичного diagnostics endpoint нет. UI regression tests передают trusted server snapshot в page httpDiagnostics callback, чтобы assertion error сохранил evidence.

Контрольные404/401/script throw и успешный reply/terminate доказывают различимость этих сценариев инструментами; не доказывают причину прежнего intermittent native failure. Успешный churn12 resets/count1 доказывает исследованные рестарты и завершение предыдущих Worker через текущий путь. Инструментация может менять тайминг наблюдения; универсальная гарантия воспроизведения/отсутствия races и sandbox не заявляются.
