# Журнал запуска и местоположение ошибки графа

`executeGraph(...,{onNodeFailure})` допускает optional observer `(callPath)=>void`. При ошибке actual atomic/composite operation или проверки её результата observer получает скопированный путь `{graph,node,contract}` от внешнего графа до текущей операции. При nested failure первое сообщение содержит точный leaf/caller chain; последующие parent сообщения могут быть короче. Ошибки вычисления аргументов принадлежат реально упавшему producer. Валидация до операции не придумывает node location.

Observer не изменяет `error.code`, `error.details`, порядок вычисления или результат. Observer exception игнорируется. Invalid non-function option отвергается. Путь не содержит аргументов, состояния, результата, ключей или native implementation. Прежние runtime/compiler conformance error vectors сохраняются.

Studio Worker сохраняет первый failure path отдельным диагностическим полем транспорта, client переносит его отдельно от semantic error details. Графовый редактор выделяет соответствующий node текущего workspace; для ошибки вложенного контракта это его call block, при исполнении раскрытого body — leaf. Полный автоматический переход в вложенный failing graph и source-map/control debugger ещё открыт.

`#execution-log` показывает actual Worker request start, успешную проверку сохранённого проекта, terminal completion/failure/cancel/deadline. «Проект проверен» относится к stored project, не утверждает проверку необработанного text candidate: текст проверяется ordinary frontend при Run. Лог не имитирует пошаговую трассу. UI событийная trace остаётся собственностью existing ReactorKernel. Путь и lifecycle — authoring diagnostics, не новое semantic IR.


## Настоящее пошаговое исполнение графа вызовов

`executeGraph(...,{onNodeEnter})` принимает optional async callback для паузы **перед actual operation**, после вычисления зависимостей и проверки policy. Event содержит только `phase: "enter"`, `callPath`, имена/типы `inputs`, тип `output`, названия `effects`/`capabilities`. Значения входов, результатов, state, error payloads и реализации не передаются. Metadata отделена копированием; изменение event не изменяет программу. Отсутствие observer сохраняет прежнее исполнение; exception/rejection observer игнорируется, AbortSignal отменяет даже неразрешённую pause promise. Trusted observers могут задержать исполнение; это диагностический интерфейс, не sandbox. Observer не служит обработчиком semantic exceptions.

Пауза следует actual demand-driven порядку: зависимости раньше consumer, memoized producer останавливается один раз, dead nodes не запускаются. Composite сначала останавливается на своей границе, затем на реальных внутренних operations с полным caller path. Atomic implementation не раскрывается. Ошибки до начала operation не создают фиктивную паузу. Standalone compiler пока не экспортирует debug hooks; числовая семантика остаётся общей.

`GraphStepper` управляет тем же evaluator. Каждый pause получает новый token. Только совпадающий token и `step`/`continue` освобождают текущую паузу; устаревшие/повторные/неизвестные команды отвергаются. Step разрешает одну operation до следующей entry; Continue отключает последующие паузы. История значений не собирается. Studio Worker принимает отдельные resume сообщения, пока ordinary execution ожидает gate; Worker termination завершает Stop/deadline. Client предоставляет `onPause` и `job.resume(mode)`; команды после terminal result не отправляются.

IDE: «Отладка» → путь/типы текущей operation → «Шаг» / «Продолжить» / «Остановить». Работает снимок проекта, переданный Worker при старте; изменения редактора не меняют этот запуск. При совпадении текущего workspace выделяется соответствующий caller block. Nested leaf path виден в панели, но автоматическое раскрытие вложенного body ещё не реализовано. Обычный Run имеет прежний 5s deadline, интерактивный debug — общий 60s deadline, включая паузы.

Область первой реализации: чистые call/dataflow графы, вложенные composites и явный порядок sequence существующего профиля. AC-065 первоначально не включала text/control IR, Map/Filter/control callbacks, UI state/event handlers и native/foreign debug. Текущая text/control реализация описана в AC-066 ниже; visual collection graph debug по-прежнему получает `UNSUPPORTED_DEBUG_PROFILE`, ordinary Run доступен. Full EMS-033 и AC-012 не закрыты. Доказательства: `tests/graph-debugger.test.mjs`, `tests/browser/graph-debugger.test.mjs`, verify check.


## Control IR и текстовое соответствие — AC-066

`executeControlIR(...,{onControlEnter})` — async диагностическая точка перед исполнением actual statement/expression, после ordinary tick/cancellation/budget checks. Event: `phase: "enter"`, `profile: "control"`, `function`, структурный `node` address, `kind`, `type` (или null), `callStack` функций и текущий счётчик `step`. `step` — существующий semantic budget counter, а не новая нумерация языка; служебные loop/invoke ticks могут создавать промежутки. Значения literal/locals/arguments/results/state/resource/future payloads не передаются. Array caller stack отделён копированием. Exception/rejection observer не изменяет semantic error; отмена завершает неразрешённую pause promise и сохраняет protected cancellation/finalization/resource cleanup.

`controlNodeEntries(fn)` определяет структурный JSON-pointer address относительно тела конкретной функции, например `/body/0/condition/left`. Lowering сохраняет реальные AST ranges в `ems-provenance/1.functions[functionId].nodes[address]`. Specializations получают собственные карты и actual function IDs. Координаты не добавляются в IR; serialize/parse/compiler/witness сохраняют прежний semantic artifact. Source-only whitespace/comments меняют sidecar, но не IR. Эти addresses относятся к конкретному IR snapshot, а не к стабильным ID после правки программы.

`runTextDraft(draft,editor,inputs,options)` создаёт свежий checked bundle с sidecar, исполняет прежний IR и добавляет `location` к diagnostic event из этого же bundle. Call IR использует прежнюю карту graph/node, control IR — function/address; неизвестное соответствие возвращает null. Пользователь не передаёт произвольную map для выполнения. Copy location не меняет sidecar/программу. Прежние maxSteps10000/maxDepth32 и effect/capability preflight текста сохраняются.

«Отладка» в text mode использует тот же Worker, Step/Continue/Stop и60s total deadline. Панель показывает actual function chain, operation address/kind/type и строку/столбец. Выделение текста использует UTF-16 offsets parser/textarea и выполняется только если текущий editor source совпадает с переданным снимком. Правка текста во время паузы сохраняет запуск снимка и исключает неверное выделение новой версии.

Составные вызовы и ленивые branches/loops исполняются обычным runtime; невыполненные ветки не создают trace. Generic lowering, exceptions, async local functions/futures, resource operations сохраняют существующие profiles. GraphStepper теперь ставит конкурентные entries в FIFO очередь: видна одна pause, token шага освобождает текущую, Continue освобождает также накопленные entries. Очередь не обещает deterministic ordering внешних futures; никакой второй scheduler/evaluator не вводится. Worker termination по-прежнему ограничивает незавершённые browser tasks.

Проверки: semantic IR roundtrip/comment shift, real pause/selected branch/loop repeats/nested function locations и compiled result; observer mutation/rejection, protected cancellation/step limits, resource cleanup после отмены в паузе, queued futures, call IR provenance; actual Chromium source selection (включая Unicode comment), nested Step/Continue6, stale edited source guard, Stop/recovery. Полный UI event/state debugger, visual collection stepping, breakpoint/Step Over/native/compiled debugging и полный AC-012 остаются открытыми. Карта координат сама по себе не доказывает полноту visual round-trip.
