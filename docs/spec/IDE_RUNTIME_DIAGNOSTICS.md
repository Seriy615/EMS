# Журнал запуска и местоположение ошибки графа

`executeGraph(...,{onNodeFailure})` допускает optional observer `(callPath)=>void`. При ошибке actual atomic/composite operation или проверки её результата observer получает скопированный путь `{graph,node,contract}` от внешнего графа до текущей операции. При nested failure первое сообщение содержит точный leaf/caller chain; последующие parent сообщения могут быть короче. Ошибки вычисления аргументов принадлежат реально упавшему producer. Валидация до операции не придумывает node location.

Observer не изменяет `error.code`, `error.details`, порядок вычисления или результат. Observer exception игнорируется. Invalid non-function option отвергается. Путь не содержит аргументов, состояния, результата, ключей или native implementation. Прежние runtime/compiler conformance error vectors сохраняются.

Studio Worker сохраняет первый failure path отдельным диагностическим полем транспорта, client переносит его отдельно от semantic error details. Графовый редактор выделяет соответствующий node текущего workspace; для ошибки вложенного контракта это его call block, при исполнении раскрытого body — leaf. Полный автоматический переход в вложенный failing graph и source-map/control debugger ещё открыт.

`#execution-log` показывает actual Worker request start, успешную проверку сохранённого проекта, terminal completion/failure/cancel/deadline. «Проект проверен» относится к stored project, не утверждает проверку необработанного text candidate: текст проверяется ordinary frontend при Run. Лог не имитирует пошаговую трассу. UI событийная trace остаётся собственностью existing ReactorKernel. Путь и lifecycle — authoring diagnostics, не новое semantic IR.


## Настоящее пошаговое исполнение графа вызовов

`executeGraph(...,{onNodeEnter})` принимает optional async callback для паузы **перед actual operation**, после вычисления зависимостей и проверки policy. Event содержит только `phase: "enter"`, `callPath`, имена/типы `inputs`, тип `output`, названия `effects`/`capabilities`. Значения входов, результатов, state, error payloads и реализации не передаются. Metadata отделена копированием; изменение event не изменяет программу. Отсутствие observer сохраняет прежнее исполнение; exception/rejection observer игнорируется, AbortSignal отменяет даже неразрешённую pause promise. Trusted observers могут задержать исполнение; это диагностический интерфейс, не sandbox. Observer не служит обработчиком semantic exceptions.

Пауза следует actual demand-driven порядку: зависимости раньше consumer, memoized producer останавливается один раз, dead nodes не запускаются. Composite сначала останавливается на своей границе, затем на реальных внутренних operations с полным caller path. Atomic implementation не раскрывается. Ошибки до начала operation не создают фиктивную паузу. Standalone compiler пока не экспортирует debug hooks; числовая семантика остаётся общей.

`GraphStepper` управляет тем же evaluator. Каждый pause получает новый token. Только совпадающий token и `step`/`continue` освобождают текущую паузу; устаревшие/повторные/неизвестные команды отвергаются. Step разрешает одну operation до следующей entry; Continue отключает последующие паузы. История значений не собирается. Studio Worker принимает отдельные resume сообщения, пока ordinary execution ожидает gate; Worker termination завершает Stop/deadline. Client предоставляет `onPause` и `job.resume(mode)`; команды после terminal result не отправляются.

IDE: «Отладка» → путь/типы текущей operation → «Шаг» / «Продолжить» / «Остановить». Работает снимок проекта, переданный Worker при старте; изменения редактора не меняют этот запуск. При совпадении текущего workspace выделяется соответствующий caller block. Nested leaf path виден в панели, но автоматическое раскрытие вложенного body ещё не реализовано. Обычный Run имеет прежний 5s deadline, интерактивный debug — общий 60s deadline, включая паузы.

Область первой реализации: чистые call/dataflow графы, вложенные composites и явный порядок sequence существующего профиля. Text/control IR, Map/Filter/control callbacks, UI state/event handlers и native/foreign debug явно не поддержаны в Studio stepping. Text debug и collection graph debug получают `UNSUPPORTED_DEBUG_PROFILE`; ordinary Run остаётся доступен. Full EMS-033 и AC-012 не закрыты. Доказательства: `tests/graph-debugger.test.mjs`, `tests/browser/graph-debugger.test.mjs`, verify check.
