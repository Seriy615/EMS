# Нормативная семантика EMS — редакция 0.1

**Задача:** EMS-010. **Связь с целью:** G-01/03/04/05/11/12.  
**Исполняемый профиль:** `ems-core-finite/1`. Контрольные векторы: `tests/fixtures/semantics.json`; команда: `npm test`.  
Этот профиль определяет проверяемое чистое ядро. Правила расширений ниже задают направление M1; до отдельных тестов они не являются реализованными возможностями.

## 1. Общая модель

Программа имеет контрактную сигнатуру, именованные входы, типизированные вызовы и возвращаемое значение. Текст и визуальная форма определяют одинаковое вычисление. Координаты, цвета и описания не участвуют в семантике. Версия графа M0 — `0.1`; версия будущего IR проверяется отдельно.

Атом — лист исполнения без раскрываемого EMS-графа. Составной вызов вводит отдельную область входов, узлов и мемоизации. Реализация, интерфейс, пакет, лицензия и видимость различаются. Замена составной реализации скомпилированной атомарной сохраняет типы, результаты и определённые ошибки. Семантическая эквивалентность проверяется, не предполагается.

## 2. Значения и числа

| Тип профиля | Допустимые значения | Недопустимые значения |
|---|---|---|
| `Number` | Конечные числа binary64, включая `+0` и `-0`, subnormal | NaN, ±Infinity, строки и неявное приведение |
| `NumberArray` | Плотная последовательность конечных Number, включая пустую | Пропуски элементов, смешанные типы, нечисловые значения |
| `Boolean` | `true`, `false` | Truthy/falsy преобразования |
| `String` | Строки хостового JS профиля | Автоматическое преобразование других типов |

`Number` — имя ограниченного типа прототипа, не окончательная замена будущих `Int*`, `Float*`, `Decimal`, `Duration` и других типов. Для binary64 используются округление к ближайшему с выбором чётного и постепенное underflow. Знак нуля сохраняется при вычислении и генерации JS. Результат каждого контрактного вызова проверяется до использования следующим узлом: выход за конечный диапазон даёт `TYPE_MISMATCH` с `received: Unknown`. Компилятор не вправе скрывать эту ошибку последующим вычислением конечного результата.

| Операция | Определение | Ошибки |
|---|---|---|
| `core.add/sub/mul` | Binary64 операция над двумя Number | Неконечный результат: `TYPE_MISMATCH` |
| `core.div` | Деление Number | Делитель `+0` или `-0`: `DIV_BY_ZERO`; неконечный результат: `TYPE_MISMATCH` |
| `core.sum` | Левое свёртывание с начальным `+0`, без изменения порядка | Пустой массив → `+0`; неконечный результат: `TYPE_MISMATCH` |
| `core.min` | Минимум; среди равных нулей выбирает `-0` | Пустой массив: `EMPTY_ARRAY` |
| `core.max` | Максимум; среди равных нулей выбирает `+0` | Пустой массив: `EMPTY_ARRAY` |

Ассоциативность вещественной арифметики не предполагается. Например, сумма `[1e16, 1, -1e16]` равна `0`. Backend не переставляет члены суммы и не применяет fast-math без отдельно согласованного профиля. Большой массив не передаётся хостовой функции через неограниченное число позиционных аргументов.

## 3. Статическая проверка

Перед исполнением проверяется весь граф, включая недостижимые узлы: существование контрактов, входов и узлов, отсутствие циклов зависимостей, уникальность имён, точное множество аргументов, тип каждого соединения и возвращаемого значения. Преобразования типов отсутствуют; `Number` и `String` несовместимы. Ссылка содержит ровно один вариант: вход, узел или литерал. Неподдерживаемый литерал даёт `UNKNOWN_LITERAL`.

Это определение семантических проверок; M0 validator не является полной реализацией всех ограничений JSON Schema/IDL. Строгость нового IR проверяется отдельным gate EMS-011.

## 4. Операционная семантика чистого графа

Состояние вызова: окружение входов `I`, карта успешных результатов `M`, стек составных вызовов `S`. После проверки графа проверяется envelope входных значений: объект, все собственные объявленные поля, правильные типы, отсутствие лишних собственных перечисляемых полей. Проверка входов следует порядку объявления сигнатуры.

Правила ссылки:

- `input(x)` возвращает `I[x]`;
- `literal(v)` возвращает типизированное `v`;
- `node(n)` возвращает `M[n]`, если он вычислен; иначе выполняет вызов узла.

Правило вызова узла:

1. Разрешить контракт и проверить его capability grants до вычисления его аргументов.
2. Последовательно вычислить аргументы в порядке портов публичной сигнатуры контракта. Перестановка полей `args` или узлов на полотне этот порядок не меняет.
3. Выполнить атом либо составной граф с отдельным `M` и расширенным `S`.
4. Проверить результат по объявленному выходному типу; сохранить успешный результат в `M`.

Вычисление начинается с `returns`; недостижимые узлы не исполняются. Общая ссылка на узел не вызывает его повторно в том же вызове графа. Новый вызов создаёт новое состояние. Аргументы не выполняются параллельно; первая ошибка прекращает вызов, последующие аргументы не вычисляются. Ошибка не превращается в успешное значение или `null`. Результат графа проверяется по типу выхода.

Граф циклов зависимостей запрещён: `GRAPH_CYCLE`. Прямая/косвенная рекурсия составных вызовов и глубина больше 32 одновременно активных графов запрещены: `RECURSIVE_COMPOSITE`. Это ограничение reference профиля; полноценная рекурсия требует отдельного control-flow IR и ресурсной модели.

## 5. Ошибки и внешние границы

EMS-ошибка содержит `name: EmsError`, стабильный `code`, сообщение и `details`. Между runtime и standalone сравниваются код, имя и определённые details; класс/stack trace хоста частью переносимого ABI не является.

| Код | Причина |
|---|---|
| `INVALID_INPUT` | Неправильный envelope входов |
| `MISSING_INPUT` / `EXTRA_INPUT` | Сигнатура входов не соблюдена |
| `TYPE_MISMATCH` | Неверный тип значения/связи или неконечный результат |
| `DIV_BY_ZERO` / `EMPTY_ARRAY` | Определённые ошибки арифметических контрактов |
| `MISSING_CONTRACT` / `MISSING_ARGUMENT` / `EXTRA_ARGUMENT` | Неразрешимый вызов |
| `GRAPH_CYCLE` / `RECURSIVE_COMPOSITE` | Запрещённый цикл/рекурсия |
| `PERMISSION_DENIED` | Требуемая capability не предоставлена |
| `UNSUPPORTED_TARGET` | Отсутствует допустимая реализация на выбранной цели |

Сырой exception доверенного host-кода в M0 проходит как host exception; полноценное преобразование FFI-ошибок относится к EMS-121. Reference registry имеет полномочия процесса и не обеспечивает изоляцию. Входы и массивы считаются неизменяемыми по договорённости доверенных операций; runtime ещё не обеспечивает ownership или защиту от мутации.

## 6. Эффекты и компиляция

`effects` описывают наблюдаемое действие; `capabilities` — требуемые grants. Это отдельные поля, а не синонимы. M0 проверяет только capability metadata; разрешение эффекта без capability broker не даёт гарантии безопасности.

Чистый standalone backend отвергает любой объявленный эффект или capability в обрабатываемом графе, в том числе в неиспользуемом узле. Он не объявляет поддержку состояния, устройств, IO, async или произвольного ESM. Каждый достижимый атом должен иметь доверенную pure-JS реализацию генерации. Неподдерживаемая операция отвергается при сборке. Backend сохраняет проверку промежуточных значений, мемоизацию, порядок портов и ошибки. Скомпилированный модуль экспортирует `execute(inputs)` и не импортирует EMS.

## 7. Нормативное направление расширений M1

Следующие правила обязательны для новых реализаций, но требуют собственных профилей и исполняемых векторов перед заявлением поддержки:

- Условия вычисляют только выбранную ветвь. Циклы и рекурсивные функции имеют явно ограничиваемый бюджет и отдельные control edges; запрет циклов dataflow не заменяет их реализацию.
- Целые типы имеют ширину и проверяемое переполнение; неявное усечение запрещено. Float32/64 и Decimal имеют отдельные правила NaN, округления, масштаба и сериализации. Расширение finite Number не происходит молча.
- `Option` и `Result` — типизированные варианты; не смешиваются с host null/exception. Pattern matching проверяет полноту.
- Эффектные вызовы имеют явный порядок и область разрешений. Оптимизация не дублирует и не удаляет действие; отказ в разрешении предшествует внешнему действию.
- Состояние принадлежит объявленной области исполнения; изменение выполняется через типизированную последовательность переходов. Между устройствами нет общей изменяемой памяти.
- Future, события и Stream объявляют порядок, cancellation, backpressure и предел очереди. При воспроизведении одного входного trace и одной политики scheduler детерминированные области имеют одинаковые выходные trace. Порядок внешних конкурентных событий не выдумывается.
- ResourceHandle имеет владельца, явное закрытие и область жизни. Выход после закрытия, двойное освобождение и запрещённое перемещение между потоками дают определённые ошибки. Завершение/отмена освобождают принадлежащие области ресурсы по объявленному порядку.
- Remote edge имеет сериализацию, auth, timeout и политику повторов; повторяемость эффекта требует idempotency/deduplication. Разделение сети не скрывается.

EMS-011 реализует версионированный IR начального профиля; EMS-012/013 расширяют грамматику и типы; EMS-014/015 — эффекты, control-flow, состояние и async; EMS-016/017 — стабильный IDL и полный conformance harness. До этого M1 целиком не завершён.

## 8. Acceptance

AC-025 требует одинаковых значений (включая знак нуля) и структурированных ошибок на векторах `ems-core-finite/1`, дополнительных отрицательных host-входах, вложенных композициях, shared nodes, порядке аргументов и больших коллекциях. Это проверка reference JS runtime и JS output, а не свидетельство нескольких ОС или настоящего браузера. Независимый переносимый target проверяет те же векторы, не определяет собственную арифметику.
