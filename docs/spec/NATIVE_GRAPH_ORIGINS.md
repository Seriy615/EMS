# Авторские графы native-программы

AC-133 связывает исходные `graph`-тела с тем же обычным редактором контрактов. Это продолжение [GRAPH_SOURCE.md](GRAPH_SOURCE.md), не новый язык или runtime.

При импорте native EMS компилятор сохраняет графовые тела отдельно от `ems-instance-module/1`. Документ `ems-instance-project/3` имеет прежние `module`, `sourceArchive`, `bodyGraph`, `invariantGraphs`, необязательный `ui` и обязательный массив `authoredGraphs`. Документы /1 и /2 остаются совместимыми; обычный текст без graph-тел не переводится автоматически в /3.

Каждая запись `{scope, graphs}` относится к одному настоящему IR-программному окружению:

- `{kind:"body"}` — реализации операций всех экземпляров;
- `{kind:"initializer",definition,field}` — начальное значение поля определения;
- `{kind:"override",instance,field}` — отдельное начальное значение экземпляра;
- `{kind:"invariant",definition,id}` — предикат инварианта.

`graphs` содержит исходные semantic graphs по настоящим function ID: узлы, версии, порты, литералы, storage ownership и activation/data connections, включая неисполняемые узлы. Логические `self`/instance обращения уже разрешены компилятором в реальные typed state bindings. Функции, упомянутые только неисполняемыми узлами, сохраняются как настоящие IR-определения с общим specialization table (без дополнительных исполняемых вызовов и без конфликтов generic IDs). Это authoring artifact, не поле semantic IR; координаты и описания живут в обычном canvas-документе после сохранения.

## Проверяемое соответствие

Получатель не доверяет архивному тексту, сохранённому хешу или приложенной копии IR. Он проверяет модуль и реальные сигнатуры, восстанавливает все фактические функции в общий located AST, заменяет заявленные graph-тела, повторно запускает общий type/effect checker и lowering. Результат каждой заявленной функции должен структурно совпасть с настоящей IR-функцией с точностью до переименования частных лексических переменных. Публичные имена и порядок параметров, типы, литералы (включая -0), операции, порядок аргументов/операторов, branches, calls, pins, policies и requirements сохраняются. Захват переменной другим binder не считается эквивалентным.

Сигнатуры — интерфейсы действительных функций того же окружения, без исполняемых заглушек. Проверка не исполняет программу, initializers или predicates и не снимает capability/effect ограничения. Импорт отказывает при stale body, несовместимом интерфейсе, неизвестном scope или небезопасной структуре данных. Accessors/symbols/cycles/sparse arrays не принимаются; getter не запускается.

Границы: 4 MiB на документ; до 2048 непустых уникальных scopes, 65536 graph nodes суммарно, до 33 graphs/1024 nodes на программное окружение; собственные данные до 200000 значений, depth256, плотный массив до20000, record до200 полей. Действуют также ограничения самого native-модуля, flow и compiler. Верификация поддерживает finite synchronous IR; не обещает source projection async/resource/foreign-профилей.

## Поведение редактора

При первом открытии перехода или инварианта исходное graph-тело используется непосредственно: те же IDs и рёбра, без повторного превращения скомпилированного PC/while в новый большой граф. Обычные текстовые функции рядом проецируются прежним механизмом; полноценный inverse произвольного structured source этим не объявляется. Если соседний текстовый helper использует конструкцию вне возможностей прежнего source-flow projector (например, try/match или вычисляемый tagged constructor), открытие смешанного canvas пока отказывает типизированно; исходник и semantic module остаются сохранёнными. Проверка origin сама по себе не обещает визуальную проекцию любого finite IR.

Initial layout назначается только новому представлению; сохранённые координаты принадлежат обычному `bodyGraph`/`invariantGraphs`. Полное Save переводит весь соответствующий scope в прежнее точное saved-flow witness и удаляет лишь заменённую source-origin запись. Остальные scopes/UI/instances/архив остаются. Редактирование начального значения удаляет только заменённый override-origin.

Переименование поля обновляет настоящие state targets, origin-ссылки, интерфейс guard и UI-привязки. Add/remove актуализирует порты; rich типы повышают старый graph profile при необходимости. Если новое имя захватило бы частную переменную или меняется recursive arity, исходный guard остаётся helper-функцией с исходными node IDs, а проверенный wrapper меняет интерфейс. Реальные и неисполняемые authoring-ссылки остаются зависимостями удаления.

Проверки: `tests/native-graph-origins.test.mjs`, `tests/browser/native-graph-origins.test.mjs`; пример `examples/native-graph-ui.ems`. UI/Worker и независимый compiler исполняют прежний настоящий semantic module. Полное применение текущего native source к существующему документу с metadata-aware diff/CAS остаётся следующей задачей; динамические instances/lifetimes и полная платформенная экосистема не завершены.
