# Типизированные данные приложения и UI — AC-124

Состояние принадлежит экземпляру ReactorSession. Значения сохраняются между
подтверждёнными событиями этой сессии; новый запуск начинает с initial из программы.
Это не запись runtime state в браузерный диск и не автоматическое восстановление
сессии после перезагрузки. Сохраняются программа, типы и её начальные значения.

## Версионированная модель

`ems-reactor/1` продолжает принимать Number, Boolean, String и NumberArray.
`ems-reactor/2` допускает канонические конечные control-типы, включая Array<T>,
Map<K,V>, Option<T>, Result<T,E> и их вложенность. Future, Stream и ResourceHandle
не являются сериализуемыми slots. Правила Map — [AC-123](TYPED_MAPS.md).

UI-приложение `ems-ui-app/2` требует reactor/2; приложение /1 требует reactor/1.
Транспорт `ems-ui-project/4` явно содержит приложение /2, exact references и sources
(возможно пустой). Старые project/1..3 не принимают приложение /2. Нельзя выдать
новую схему за старую, изменить только одну из связанных версий либо подменить
сохранённый тип initial. Прежние проекты сохраняют прежнюю сериализацию.

Типы rich slots проверяются общим parseControlType/assertControlValueType.
Дополнительный boundary требует enumerable own-data values без getters,
неплотных массивов, символов и произвольных host objects, глубину не более64,
строку не длиннее262144 code units. Логических элементов вложенных коллекций —
не более10000 на значение. Сохраняется общий предел1MiB UI project,100 slots,
100 handlers и существующие runtime/Worker/policy limits. Это reference runtime,
а не sandbox произвольного host-кода.

## Обычные контракты состояния

Для каждого slot есть `state.<id>.read() -> T` и
`state.<id>.write(value:T) -> T`. В общем графе у записи обычный typed вход
значения и activation ports; у чтения — typed выход. Read/write имеют реальные
state.read/state.write effects и capabilities. Богатые значения используют
алгебраический valueProfile и private kernel witness `ems-state-algebraic/1`;
конечные прежние сигнатуры сохраняют `ems-state-finite/1`. Подмена callback,
сигнатуры или valueProfile теряет witness. Caller metadata не становится binding.

Все чтения и записи работают через существующую транзакцию события. Значения
копируются при чтении, записи и snapshot. FIFO сохраняется. Ошибка типа, ошибка
вычисления, отмена или исчерпание бюджета не подтверждают частичные изменения
словаря/массива. Откат локального состояния не отменяет сторонние внешние эффекты.
Standalone использует тот же ReactorKernel и проверку данных; schema выбирается
компилятором из программы, пользовательские options её не переопределяют.

## Транспорт и связь UI

Типизированные initial и event literals сохраняются с объявленным типом.
Вложенный Number -0 не превращается в0; String "-0" остаётся строкой. Project/4
использует точную JSON запись signed zero внутри rich values. Числовые значения
прежнего envelope по-прежнему используют прежний type-aware codec. Map в literal
аргументе события получает тип из сигнатуры настоящего handler.

Параметр handler можно привязать к literal или typed slot. Неверный тип отвергается
при linking, до эффекта. DOM properties по-прежнему принимают свои семантические
типы, например text:String. Явная привязка `{state:"bag",format:"json"}` преобразует
конечные данные в JSON-текст с сохранением -0; Runtime, Worker и standalone
используют один formatter. Это отображение всего значения, не произвольная
JavaScript-проекция/вычисление в браузере.

В конструкторе в разделе данных доступны полные типы, создание и редактирование
существующих initial, default для выбранного типа, JSON-привязка к text и обычный
граф обработчика. Rich type либо JSON binding явно поднимают сохранённый профиль
через проверенную транзакцию редактора. Undo восстанавливает прежний документ.
Подтверждённое значение формы фиксируется при нажатии кнопки, до очереди preview
restart: поздняя перерисовка не подменяет выбранную привязку или введённые данные.

Полноценные контрактные instances/transitions/invariants, долговременное storage,
миграция типов/переименование slots со всеми ссылками, native UI implementations
и полный text/visual inverse — следующие самостоятельные части глобальной цели.
