# Обновление оболочки и восстановление PWA

Основной экран показывает хеш сборки и предлагает проверку обновления. Загрузка
регистрации, установка и активация имеют отдельные конечные ожидания; после
неудачи кнопка снова доступна. Установка новой оболочки не перезагружает открытые
редакторы без действия пользователя. Активируемый worker должен сообщить тот же
хеш, что `/api/release` с `no-store`. Несовпадение требует новой проверки.

Для старых установок, включая 9d802b08, существует `/web/update.html`. Страница и
её entrypoint намеренно не включены в offline shell, поэтому старый worker
пропускает их в сеть. Recovery helper запрашивается с отдельным сетевым query;
текущий worker также пропускает этот запрос. Явная кнопка проверяет сервер,
обновляет регистрацию, дожидается worker и проверяет его хеш перед активацией.
При успехе открывает проекты; при ошибке остаётся на странице с объяснением и
доступной повторной попыткой. Удаления регистраций, localStorage/IndexedDB,
проектов или черновиков нет. Перед действием пользователь сохраняет редакторы.

Таймеры ограничивают ожидание интерфейса и очищают слушатели; они не увеличивают
лимиты выполнения программ и не останавливают внутреннюю браузерную загрузку SW.
Сетевая недоступность или неуспешная установка показываются как ошибка, а не
как бесконечный статус загрузки. Причина конкретной сетевой ошибки на физическом
устройстве владельца не устанавливается только по показанному старому хешу.

UI-конструктор повторно использует один проверенный снимок документа, возвращая
изолированную копию для чтений. Ключ — exact source, registry identity, записи
реестра и их сериализуемые интерфейсы. Изменение исходника, undo/redo, удаление,
подмена или изменение интерфейса реестра сбрасывает снимок. Неуспешная проверка
не превращается в успешное чтение старого документа. Сохранение, изменения,
runtime и compiler по-прежнему валидируют свои действительные данные.
