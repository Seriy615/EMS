# Типизированные словари EMS — AC-123

`Map<K,V>` — значение общей системы типов control IR2. Ключ K — только
`String`, конечный `Number` или `Boolean`; V — конечный сериализуемый тип:
примитив, массив, Option, Result или другой Map. Ключи сравниваются строго,
без преобразований: Number 0 и -0 — один ключ, строки чувствительны к регистру.
Future, Stream и ResourceHandle внутри словаря запрещены.

Внешнее представление: `{ "tag": "Map", "value": [[key,value], ...] }`.
Это упорядоченные уникальные записи, а не произвольный объект JavaScript или
нативный JS Map. `__proto__` и `constructor` — обычные строковые ключи.
Валидация принимает только dense own-data массивы/пары и plain tagged record
ровно с tag/value. Accessors, holes, symbols, лишние поля, наследованные
значения и повторяющиеся ключи отклоняются; getters не вызываются.

Словари неизменяемы. set заменяет существующее значение на его месте, новый
ключ добавляет в конец. Замена сохраняет исходное представление ключа, включая знак нуля. remove отсутствующего ключа возвращает равное значение.
keys/values обходят записи в порядке добавления. Равенство Map сравнивает
множество ключей и структурные значения независимо от порядка записей.
Вложенные Map сравниваются тем же правилом; массивы сохраняют значимость порядка.
Внешние входы/выходы атомов копируются, операции не меняют переданный словарь.

## Обычные атомарные контракты

| Контракт | Входы | Выход |
|---|---|---|
| std.map.empty | — | Map<K,V> |
| std.map.fromArrays | keys:Array<K>, values:Array<V> | Map<K,V> |
| std.map.size | map:Map<K,V> | Number |
| std.map.has | map:Map<K,V>, key:K | Boolean |
| std.map.get | map:Map<K,V>, key:K | Option<V> |
| std.map.getOr | map:Map<K,V>, key:K, fallback:V | V |
| std.map.set | map:Map<K,V>, key:K, value:V | Map<K,V> |
| std.map.remove | map:Map<K,V>, key:K | Map<K,V> |
| std.map.keys | map:Map<K,V> | Array<K> |
| std.map.values | map:Map<K,V> | Array<V> |

get возвращает Some(value) или None. getOr — обычный eager-вызов: fallback
вычисляется как аргумент даже при существующем ключе; он не заменяет lazy if.
fromArrays требует одинаковую длину (`MAP_LENGTH_MISMATCH`) и уникальные ключи
(`DUPLICATE_MAP_KEY`), не выбирает неявно первое/последнее значение.

Текстовый checker выводит K/V из входов и контекста результата. Пустой словарь
требует контекст, например `let counts:Map<String,Number> = std.map.empty();`.
Конкретные атомы получают канонические ID `std.map.<operation>.K<hex>.V<hex>`;
Registry восстанавливает их по закрытому рецепту без plugin lookup/выполнения
внешнего кода. Подмена implementation/signature теряет intrinsic witness.
Каталог `ems-stdlib-catalog/4` публикует 10 Map и 10 Array templates.

В графе используются те же обычные карточки с typed value ports и activation
ports. Тип значения/элемента и тип ключа задают конкретную специализацию каталога.
Переменная Map имеет тот же вход записи, initial и текущий выход, shared storage,
удаление и undo. Автоматических соединений нет. Литералы редактируются через
проверяемый JSON; создание словаря можно выразить fromArrays или empty/set.

Поддерживаемая проекция source→обычный граф допускает algebraic IR с вызовами
словарей, generic helpers, изменяемыми переменными и обходом typed массивов.
Snapshot богатого значения — однократно записываемый контракт хранения, поэтому
последующие записи оригинала не меняют ранее захваченный результат. Match,
constructors, ошибки и другие не реализованные проекцией узлы явно отклоняются;
исходник сохраняется. Это не заявление о полном обратимом text/graph редактировании.

## Пределы и самостоятельные приложения

На одно проверяемое значение — максимум 10000 логических элементов всех
вложенных коллекций: запись Map считается одним элементом, структурная пара
не добавляет два элемента; массивы значений учитываются рекурсивно. Дополнительно
действуют прежние пределы типов, source/IR, графа, документа, Worker и shared work
budget. Внутренняя работа атома ограничена размером коллекции; каждая запись не
объявляется отдельным шагом IR. Это reference implementation, не arbitrary-code sandbox.

Runtime, cold IR parse, обычный Worker и standalone JS используют общую проверку
значений, операции и равенство. Публичный sealed контракт с Map в сигнатуре либо
объявленных ошибках требует `ems-atomic-package/6`, `ems-tagged-values/2`.
Версии 1..5 не принимают Map в публичном ABI; прежние программы по-прежнему
экспортируются как /5 с tagged-values/1. Локальное использование Map внутри
пакета без Map в публичных типах не расширяет его внешний ABI. Lock сохраняет
подлинные Map intrinsics `ems-stdlib-typed-map/1`; cold Registry восстанавливается.

Пример: `examples/dictionaries.ems` считает повторения слов, включая произвольные
строковые ключи. Постоянные UI state slots пока ограничены прежними типами;
локальные Map внутри обработчиков могут вычислять значения для этих slots.
Native/FFI Map ABI, Set/Record, полная inverse projection и прочие части глобальной
цели остаются открытыми; этот срез их не подменяет.
