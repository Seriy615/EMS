# Одна переменная, несколько обычных вызовов — AC-117

Статус: reference slice EMS-043/044. Это расширение существующего flow/IR2,
а не отдельный рантайм или завершённый text/visual roundtrip.

## Семантика и транспорт

`ems-contract-flow/3` сохраняет rich типы /2 и все прежние порты. Каждый вызов
`std.storage.Variable@1.0.0` имеет optional data input `value:T`, current-value
output `T` и activation `enter→next`. Вызов записывает свой вход при активации;
чтение выхода не активирует ни его, ни другие вызовы.

Первая нода переменной содержит `valueType` и `initial`. Дополнительный вызов
содержит `valueType` и `storage:<owner-node-id>` вместо `initial`. Это статическая
типизированная привязка к тому же экземпляру локального хранения. Она не передаёт
значение по проводу, не задаёт порядок и не связывает активации автоматически.
Все вызовы остаются нодами того же контракта с теми же входами и выходами.

Владелец обязан быть Variable с initial в том же артефакте; типы совпадают точно.
Цепочки привязок, self-binding, неизвестные/непеременные владельцы и одновременные
initial/storage отвергаются. /1 и /2 не принимают новое поле молчаливо.
Пределы /2 для значений, узлов и связей сохраняются.

Один initial создаётся на экземпляр перед выполнением вызова программы, даже
если нода-владелец недостижима, а используется только другой вызов или его выход.
Все его вызовы читают текущее значение одной ячейки. Каждый новый вызов программы
создаёт новые локальные ячейки; persistent UI state по-прежнему принадлежит
транзакционному UI kernel и не подменяется этими локальными переменными.

Компилятор связывает вызовы одной переменной с одним typed IR2 local. Порядок
элементов nodes не меняет lowering. Work ledger, политика, ошибки и standalone
используют существующие механизмы. SVG инициализирует экземпляр один раз, а записи
подписывает именем той переменной, к которой они привязаны.

## Редактирование

После добавления переменной её именованный вызов появляется в обычном каталоге.
Перетащите его на холст и соедините вход записи/активации и выходы как у остальных
контрактов. Новых связей, branch/body blocks и автоперестройки графа не возникает.
Карточка показывает имя общей переменной; свойства позволяют открыть владельца.
Начальное значение и тип редактируются через любой её вызов.

Переименование владельца обновляет привязки. Изменение типа распространяется на
его вызовы и разрывает несовместимые аргументы/потребители. Выбор того же типа
ничего не отключает. Добавление rich atom/input/result не понижает профиль /3.
Удаление отдельного вызова разрывает только его data/control wires. Если удалён
носитель initial, первый оставшийся вызов по id получает прежний initial, а
остальные привязки указывают на него. Это сохраняет общую переменную и разрешает
удаление; никакие новые data/control wires не создаются. Undo возвращает точный
документ, включая прежнего владельца и позиции.

## Существующий source → обычный граф

`sourceContractFlow` работает с проверенным finite IR2. Теперь поддерживает
динамические initializer expressions, сколько угодно write sites в пределах
общего лимита256 нод, присваивания как выражения, while/if/break/continue,
for по NumberArray и короткие &&/||. Каждая переменная — один экземпляр;
декларация выполняет обычную запись initializer, дальнейшие присваивания —
обычные вызовы той же переменной. Инициализация внутри цикла выполняется заново
при входе в декларацию. Отдельные одинаковые имена в независимых scopes не
сливаются. Shadowing внешнего имени по-прежнему запрещён frontend.

Чтение mutable local и результат присваивания фиксируются обычными value
contracts. Поэтому `x + (x = 3)` сохраняет чтение левого x до правой записи.
for сохраняет iterable один раз, затем использует обычные index/length/comparison,
Variable, If и value-less Begin/End. continue выполняет увеличение индекса,
break выходит после цикла. Непустой доступ at достигается только после проверки
индекса по длине исходного снимка. Изменение исходной переменной-массива не
изменяет уже выбранный iterable. &&/|| вычисляют только нужную правую часть;
развилка/промежуточное значение представлены обычными контрактами.

[Текстовый пример](../../examples/shared-variable-flow.ems) и
[редактируемый проект](../../examples/shared-variable-flow.ems-project.json):
[1,2,3,4,5], skip2, stop5 →8; [3,4], skip0, stop99 →7.

Исходный UI сохраняется до Apply; incomplete draft не заменяет рабочий handler.
AC-121 добавляет [раскрываемые source helpers](FLOW_COMPOSITES.md). Пользовательский index syntax с отдельным error ABI,
расширенные IR profiles, явная дополнительная policy и полная двусторонняя
проекция текста пока остаются отдельной работой. [AC-119](SAVED_SOURCE_FLOW.md)
открывает поддерживаемые сохранённые source-документы обычным canvas и сохраняет
самостоятельный flow рядом с исходником; остальные legacy-профили остаются
в прежнем editor. Общий graph artifact /3 доступен canvas/CLI/UI.
