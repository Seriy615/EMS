# EMS IR v1 — начальный типизированный профиль

**Задача:** EMS-011. **Цель:** G-02/03/11/12. **Acceptance:** AC-026.  
Схема: `schemas/ir.schema.json`; реализация и строгая проверка: `src/ir/index.mjs`. Runtime validator не требует внешнего JSON Schema engine. Структура схемы описывает формат; типы связей, версии контрактов, уникальность и отсутствие циклов проверяются семантически.

## Артефакты и границы

В начальном профиле проверенный M0 graph служит call-HIR: именованные входы, ссылки и типизированные сигнатуры разрешаются перед lowering. Это ещё не полный AST/HIR языка с control-flow и generics. Текстовый M0 frontend и visual graph проходят один lowering; полноценный parser относится к EMS-012.

Семантический артефакт имеет `schemaVersion: ems-ir/1` и `profile: ems-core-finite/1`. Граф `0.1` и IR v1 — разные форматы. Новая несовместимая версия отвергается с `IR_VERSION`, неподдерживаемый профиль — с `UNSUPPORTED_PROFILE`; автоматической миграции нет. Расширение для effects/control/state требует отдельной согласованной версии или профиля и векторов.

IR хранит идентичность/версию программы, упорядоченную публичную сигнатуру входов, выход, типизированные операции и возвращаемую ссылку. Каждая операция содержит `id`, точные `contract.id/version`, `arguments` в порядке портов контракта и проверяемый выходной `type`. Ссылки имеют явный `kind: input | node | literal`. Типы входов, литералов и результатов проверяются; неизвестные поля отвергаются.

`lowerGraphToIR` проверяет graph/HIR и строит IR. `graphFromIR` проверяет IR и связывает его с reference исполнителем. `executeIR` и `compileIRToJS` используют существующие семантические механизмы, не создавая второй язык. Вложенные composite проверяются на чистоту, включая неиспользуемые узлы. Эффекты/capabilities несовместимы с этим профилем.

Версия каждого непосредственно вызываемого контракта должна точно совпасть с registry; замена даёт `CONTRACT_VERSION`. Эта проверка не заменяет lockfile, хеш бинарника и transitive dependency lock: пакетная совместимость и provenance реализаций — EMS-016/M5. Registry и emitJS пока доверенные, изменяемые host-компоненты.

## Сериализация

`serializeIR` повторно проверяет и нормализует артефакт. Порядок полей задан форматом, операции сортируются по ID по кодовым единицам строки. Порядок аргументов задаётся публичной сигнатурой, порядок объявления входов сохраняется как часть диагностики входного envelope. Перестановка узлов или полей `args` в исходном графе не меняет результат сериализации. Имена входят в идентичность; alpha-equivalence переименований пока не реализована.

Конечный Number записывается JSON-числом; отрицательный ноль — строковым токеном `"-0"` только в typed Number/NumberArray. Для `String` тот же текст остаётся строкой. Это сохраняет знак нуля при JSON round-trip, который обычный `JSON.stringify(-0)` теряет. NaN, Infinity, sparse arrays и неподдерживаемые кодировки отвергаются. Входы исполнения могут содержать обычные JS числа, транспортная кодировка применяется к литералам IR.

Canvas, описания и source maps не хранятся в семантическом IR. `graphProvenance(graph, source)` создаёт sidecar `ems-provenance/1` со ссылками node ID → JSON Pointer. Он не влияет на сериализацию. Полные позиции текстового AST и связывание редактирования обеих форм — EMS-012/032; pointer не выдаётся за полный текстовый source map.

## Исполняемый путь

```bash
node tools/ems.mjs ir examples/avg5.graph.json --out dist/avg5.ir.json
node tools/ems.mjs text-ir examples/avg5.ems --out dist/avg5-text.ir.json
node tools/ems.mjs ir-run dist/avg5.ir.json '{"times":[12.4,11.85,13.2,12.1,14]}'
node tools/ems.mjs ir-build dist/avg5.ir.json --out dist/avg5-from-ir.mjs
```

Первый и второй артефакты совпадают побайтно. Экспортированный модуль содержит проверку входов и промежуточных результатов и исполняется без импорта EMS. `tests/ir.test.mjs` дополнительно запускает его отдельным процессом из временной директории вне проекта.

## Критерии AC-026

Проверяются round-trip всех 28 векторов ядра, совпадение text/graph IR, независимость от canvas и порядка хранения, типы и pinned versions, неизвестные версии/профили/поля, неверные ссылки, циклы, порядок портов, ошибки литералов и эффекты во вложенных composite. Проверка Node output независимого от EMS не закрывает P1/AC-018. M1 остаётся открытым до EMS-012..017.

## Профиль последовательных эффектов — EMS-014

`ems-effects-finite/1` использует те же значения, ссылки и вызовы, но добавляет `policy: { effects, capabilities }` на уровне программы и каждой операции, а также `sequence: [nodeId, ...]` и root `requirements: { effects, capabilities }`, сохраняющий требования публичного интерфейса программы отдельно от computed policy. `lowerGraphToIR(graph, registry, { profile: EFFECT_PROFILE })` вычисляет декларации транзитивно; `graphFromIR` повторно вычисляет их по linked registry и отвергает несовпадение (`EFFECT_MISMATCH`), в том числе попытку удалить эффект. Массивы policy канонически отсортированы. Сортировка операций при сериализации не меняет порядок `sequence`.

В исходном graph `0.1` поле `sequence` — явный список вызовов, выполняемый перед `returns`. Он не содержит дублей и неизвестных ID; включает все top-level узлы с транзитивными effects или capabilities. Вложенный composite с наблюдаемыми действиями имеет собственный список. Если sequenced вызов зависит от другого sequenced вызова (в том числе через чистый промежуточный узел), зависимость должна предшествовать ему в списке. Ошибка структуры/порядка — `EFFECT_SEQUENCE`; весь вложенный план проверяется до первого host-вызова. Можно включить чистый узел, чтобы выполнить его и обнаружить ошибку до следующего действия. Остальные чистые вычисления сохраняют demand-driven семантику. Успешные результаты мемоизируются: ссылка из `returns` не повторяет действие. Runtime ожидает завершения каждого async host-вызова; ошибка прекращает последовательность без rollback уже выполненных действий.

`executeIR(ir, inputs, registry, { capabilities, allowedEffects })` использует общий runtime и AC-029 preflight. Reference graph без `sequence` сохраняет старый demand-driven профиль; effect IR требует явную последовательность для всех наблюдаемых узлов. Это совместимость с M0, а не обещание полной семантики control-flow/async EMS. AST effect pass и straight-line textual lowering связаны с этим профилем по AC-031 (см. `TYPE_CHECKING.md`).

Чистый `ems-core-finite/1` отвергает наблюдаемые контракты и непустые последовательности, включая вложенные. `compileIRToJS` отвергает программы с реальными effect/capability declarations с `UNSUPPORTED_TARGET`: portable effect binding/linker пока не реализован. Чистые явные sequences исполняются и экспортируются с сохранением ошибок и memo; сам профиль не является причиной отказа. `compileStandaloneJS` также проверяет транзитивные декларации, включая неиспользуемые composite, и сохраняет чистые явные последовательности.

Воспроизводимый trusted stdout пример: `node examples/effect-sequence.mjs` печатает `first`, затем `second`, хотя хранение узлов обратное. Это реальный host console adapter, не sandbox, File API или полноценный compiler backend. Evidence: `tests/effect-ir.test.mjs`, AC-030. Canvas/provenance по-прежнему вне семантического IR; pinned direct versions не заменяют transitive implementation lock.
