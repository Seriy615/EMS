# Структурный EMS-модуль как атомарный пакет (AC-094)

buildAtomicPackage(ir, registry, options) связывает существующие pure IR1 и синхронные finite/error/algebraic IR2 через existing JS compiler. Возвращаются manifest и files: module.mjs, contract.json. Нет EMS IR/graph/canvas/source-map файла; модуль содержит compiled implementation/helpers. Структурная атомарность означает отсутствие раскрываемого EMS-графа у потребителя, не secrecy/DRM. License/visibility не выводятся из kind.

Параметры: id — public contract ID; packageId — отдельный package ID (default id.package); version — contract version; packageVersion — отдельная package version (default contract version); target только js-esm-sync/1. Contract signature переносит ordered inputs/output. Public ABI: Number/Boolean/String/NumberArray, synchronous execute(inputs, options), pure effects/capabilities. Helpers могут содержать условия, циклы, рекурсию, errors и внутренние algebraic values. Async/futures/streams/resources/local mutation effects/system capabilities/nonprimitive public ABI явно отклоняются, не понижаются. Это начальный linker/sealing slice EMS-060, а не полный production backend или закрытый EMS-062.

Зависимости: genuine coreIntrinsic implementations либо explicitly trusted packages, загруженные registerTrustedAtomicPackage с exact executor/emitter/id/version/input/output/purity metadata. Одного названия/неизвестного trusted host emitJS недостаточно. Metadata drift после загрузки отвергается. Re-sealing linked consumer поддержан, package code bounded2MiB. Generated code в build не импортируется/не исполняется; recognized trusted compiler hooks входят в границу доверия.

Manifest ems-atomic-package/1 имеет отдельные package id/version/target, contract id/version/kind/inputs/output/effects/capabilities и module {file:module.mjs,sha256}. Closed own data fields, safe fixed file, synchronous target and primitive types validated. SHA-256 — existing Web Crypto; unavailable hash не заменяется слабой схемой. Manifest фиксирует module bytes, не доказывает owner authenticity или отсутствие вредного trusted JS.

registerTrustedAtomicPackage(registry, manifest, source) — явное доверенное ESM исполнение, не автоматический library import/sandbox. Hash mismatch и существующий contract ID проверяются до module evaluation. При корректном trusted import используется существующий pinned SDK/private callback provenance; registry видит только atomic signature, graph отсутствует. Input expressions re-emission uses Object.fromEntries, включая __proto__. execute/emitJS позволяют вызвать атом из нового graph/control program и повторно скомпилировать потребителя без EMS dependencies. Runtime options применяются внутри synchronous module; pure graph compiled consumer использует existing default per-atom budget. Shared cross-boundary budget/source maps/async/native ABI and package signatures требуют отдельного gate.

CLI:
    node tools/ems.mjs module-seal examples/factorial-sum.ems --entry main --id sealed.Factorials --out dist/factorials

CLI проверяет/builds всё до записи файлов; ошибки unsupported target/ABI/identity не создают fake package. Filesystem failures/overwrite policy следуют initial reference CLI, installation transaction не заявляется.

IDE: в настройках кода задайте ID нового контракта и выберите «Скачать атомарный контракт». Скачивается TAR двух actual package files; экспортирует click-time checked draft, не live diagnostic state. Import downloaded JS в IDE автоматически не выполняется. Author project/source остаётся inspectable. Package.execute не имеет зависимости от EMS IDE/cloud и работает Node/Web; platform-native support этим результатом не объявляется.

Acceptance: interpreted original vs generated module vectors, user error/type/-0, actual import into new graph, consumer compiler/re-seal, fresh external process, downloaded browser archive after EMS origin shutdown, closed/hash/signature/target/unknown-plugin refusal. Полные rich contract IDL conditions/errors public manifests, async/native/FFI/platform packaging/production source maps remain separate.

Public IDE CSP не разрешает dynamic data-URL code evaluation. Export/download не ослабляют эту политику; trusted loader применяется в Node или explicit execution realm с разрешённым module mechanism. Standalone exported module загружается из своего static host как обычный ESM file. Public QA builds через HTTPS, затем trusted Node import/consumer compile outside IDE; actual downloaded artifact browser proof выполняется на отдельном static host после shutdown EMS origin.

## Public typed user-error ABI v2 (AC-095)

Новый build выдаёт ems-atomic-package/2 с errors {model:ems-user-throw/1,types:[canonical sorted unique control type names]}. Types включают все throw value types в control functions, в том числе caught/unreachable throws, и ошибки v2 sealed dependencies. Это conservative potential set, не точный список escaping paths. Массив максимум64 типов, bounded names, ResourceHandle/Stream/Future errors не разрешены. Pure core intrinsics имеют ordinary semantic errors, не user throw types.

В module.mjs включён immutable exported packageInterfaceJSON: package/contract identity, target, ordered public signature/purity и error model. Loader сначала проверяет module SHA, затем в explicit trusted import realm проверяет exact description перед registration/create factory. Manifest-only change не может удалить errors/изменить output/package ID при прежнем module hash. Hash/authenticity различны: trusted JS top-level может исполняться при explicit import, это не sandbox или owner signature.

ems-user-throw/1 уже используется общим runtime/compiler: error has own emsThrow/code/valueType/value, payload typed and cloned; user message generic, payload не переписывается в message. Consumer try/catch узнаёт String/Number/Option/Result ошибки imported atom так же, как исходной программы. Tested -0 и tagged payloads preserve semantics in interpreter/compiler/browser. STEP_LIMIT/CALL_DEPTH/CANCELLED terminal ошибки не превращаются в user throw и bypass typed catch. Payload size/redaction и authorization обычных user result/error channels не объявляются диагностической политикой.

V1 packages явно импортируются как legacy; versioned v2 module нельзя понизить до v1 manifest для обхода description check. Loaded v1 dependency не имеет checked complete error ABI, поэтому новый v2 build/reseal отвергает её с UNSUPPORTED_ERROR_ABI вместо обещания пустого errors set. Owner может явно пересобрать исходный EMS модуль в v2. Graph/IR1 consumers получают union errors своих sealed v2 dependencies; internal graph/source не попадает в manifest.

Compiled/runtime function behavior не переписан ради ABI: existing envelopes and catches kept. Limits continue existing per-atom rules; explicit shared budgets, async/nonprimitive public returns, native ABI, production maps/signatures/IDL error conditions remain open.

## Explicit package execution limits v3 (AC-097)

buildAtomicPackage принимает maxSteps (default100000) и maxDepth (default64). Новый manifest ems-atomic-package/3 содержит limits {model,maxSteps,maxDepth}; оба положительные safe integers, maxDepth≤256. Limits включены в immutable packageInterfaceJSON и module SHA. Manifest-only изменение величин/model или downgrade v3→v2/v1 отвергается. V1/v2 loader сохранён для legacy; новые v3 пакеты не линкуют v2 без checked limits (UNSUPPORTED_BUDGET_ABI), v1 ранее отвергается за отсутствие checked errors. Пересоберите исходный EMS модуль для явной ABI.

ems-control-steps/1 использует существующие control compiler ticks (function entry, statements и expressions), maxDepth считает активные EMS function calls, включая entry. ems-graph-steps/1 считает одну единицу за вход в root/composite graph и за каждый demanded/explicit-sequence node; повторное memo-reference не тратит новый node tick, unreachable nodes не исполняются. Composite node оплачивается после аргументов перед входом в его граф. maxDepth считает root/composite graph activations. Существующий static compiler recursion/expansion guard32 сохранён. Эти две единицы работы не объявляются взаимозаменяемыми: model фиксирует semantics.

Module.execute(inputs,options) валидирует requested budget, по умолчанию берёт package values, затем ограничивает каждый параметр package maximum. Smaller direct budgets работают; larger не повышают ceiling. INVALID_BUDGET не превращается в допустимое значение. Каждый invocation имеет свежие counters, включая вызов после ошибки. Imported execute, consumer emitJS и re-sealed consumer используют тот же compiled atom и сохраняют его ceilings. Outer consumer limits не заменяют внутренних package limits; стандартный host invocation передаёт signal/state, а не общий counter. Control cancellation сохраняет existing semantics; новый graph instrumentation не добавляет signal transport.

Per-package counters — не глобальный shared budget, не wall-clock/CPU/memory bound, не sandbox: стоимость одной host/intrinsic array/string операции и trusted JavaScript не измеряется ticks. Вложенные sealed packages имеют независимые counters; их ceilings не сливаются с outer limits. Для всей logical program нужен отдельный shared-budget protocol. Async/rich public ABI, source maps, native targets и package signatures по-прежнему открыты. Acceptance: direct/imported/compiled/resealed ceilings, recursion, memo/sequence/composite accounting, invalid/tampered/downgraded metadata, legacy v2 refusal, независимые Browser и fresh Node files.

## Shared work budget ABI v4 (AC-098)

Новые buildAtomicPackage exports используют ems-atomic-package/4 и budgetProtocol:ems-work-budget/1 в manifest/module descriptor. Old v1/v2/v3 load разрешён явно, но v4 link/reseal отвергает v3 без reviewed shared protocol с UNSUPPORTED_SHARED_BUDGET_ABI (v1/v2 ранее за missing errors/limits). Manifest-only removal/protocol downgrade не подменяет module description.

createWorkBudget(maxWork) из src/semantics/work-budget.mjs создаёт frozen same-realm ledger с private remaining/exhausted и методами charge(count=1), fork(limit), snapshot(). Значения positive safe integers; exhausted STEP_LIMIT sticky. Fork имеет свой ceiling и списывает ту же charge из каждого ancestor, без двойного списания в одном ledger. Собственное превышение закрывает child, не тратит remaining ancestor; ancestor exhaustion также закрывает child. Snapshot содержит только maxWork/remaining/exhausted, не inputs/values, но это execution metadata, не гарантия скрытия control-flow/timing.

Control runtime/compiler ticks и graph runtime/compiler activations/nodes используют один options.workBudget. Default root ledger maxWork=options.maxSteps??100000. Control имеет прежний local step/depth check; graph memo references не создают новый tick. CompileControl host adapter для atomic contracts не считает synthetic graph wrapper как отдельную EMS работу; настоящий composite граф считается теми же units, что в runtime. emitJS получает optional context.options expression; v4 sealed emitter передаёт workBudget/signal/state, сохраняя local package values и не подменяя их caller maxDepth/maxSteps. Graph/code IR не содержит ledger, source/canvas identity не меняется.

Каждый v4 package execute создаёт fork с потолком min(package.maxSteps,direct requested maxSteps), либо root ledger, если ancestor отсутствует. Тем самым limit ограничивает всю работу package subtree (control ticks + graph activations/nodes в descendants); local limits.model/depth controls также действуют. Большой внешний ledger не отменяет subtree ceiling. Новый top-level call без явно переданного ledger получает новое состояние; повторный call с exhausted ledger отвергается. Это изменение относительно v3 independent per-atom counting, поэтому versioned ABI обязательна.

Конкретная charge unit — semantic control tick или graph activation/node tick; сумма heterogenous units детерминирована правилами, не соответствует CPU time. MaxDepth пока local per package/compiler; shared cross-package depth, async/distributed budget ownership, Worker structured-clone transport (ledger methods не сериализуются), wall-clock/memory/native/host instrumentation не объявлены готовыми. Standard runtime async calls могут делить in-process ledger, но публичные sealed packages остаются synchronous primitive ABI. Trusted opaque host/legacy implementations могут игнорировать protocol: frozen fields validation не доказывает authenticity callbacks и не является sandbox. V4 builder принимает только known builtins/composites и reviewed sealed implementations.

Acceptance: aggregate interpreter/compiler charges и exact boundaries, mixed graph/control/composite memo, ancestor/fork sticky exhaustion, subtree cap under generous parent, typed catch refusal, schema downgrade/legacy rejection, linked standalone files in isolated static browser origin and fresh Node process без EMS dependencies. IDE Worker API/default transport не выставляет callable budget objects и не сохраняет их в project files.
