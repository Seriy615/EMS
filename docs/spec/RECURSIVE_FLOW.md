# Рекурсивные составные контракты — AC-122

Статус: reference slice EMS-043/044, частичное продвижение G-02/03/05/11/12/14.
Рекурсия использует существующие функции typed IR2 и его work/depth ledger.
Нового evaluator, безлимитного JS-стека или автоматического раскрытия дерева
вызовов в редакторе нет.

## Версия и область имён

`ems-flow-project/3` имеет прежние поля /2 плюс обязательный
`callProfile: "ems-flow-recursive/1"`. `contracts` присутствует и при пустой
библиотеке: entry может вызывать сам себя. Корневой граф является таким же
внутренним вызываемым контрактом, как остальные definitions. Он объявляется
и компилируется один раз; дубликат entry в `contracts` запрещён.

/1 и /2 сохраняют прежнее ограничение ацикличной библиотеки. Пропущенный или
неизвестный callProfile в /3, лишнее поле в старой версии, неверная версия
контракта и несовместимые порты отклоняются. Существующие DAG-файлы не меняются
при открытии. Добавление self/ancestor/entry call в редакторе — явное действие,
которое атомарно повышает документ до /3. Позиции и провода не создаются и не
перестраиваются; undo возвращает прежнюю версию документа. Добавление нового
определения или изменение типа не понижает /3 обратно в /2.

Source adapter обнаруживает циклы в конечном наборе графов функций, включая
entry, и сохраняет /3. Он не разворачивает рекурсию и не теряет function boundaries.
Остальные ограничения finite source profile AC-117/121 остаются действительными.
Manager, workspace import/export/copy, UI witness и CLI сохраняют callProfile;
compiler/Worker принимают его явно через options. Неявного игнорирования версии нет.

## Эффекты и права

Вначале собираются прямые эффекты и capabilities каждого графа и его зависимости.
Затем множества объединяются вдоль всех call edges до устойчивого результата.
Монотонное вычисление ограничено числом определений (не более32 плюс entry).
Даже взаимные вызовы без прямых effects наследуют state read/write зависимостей.
Порядок definitions не определяет политику.

Все тела после этого проходят обычную typed/activation/data-availability
валидацию. UI profile допускает только реальные kernel state bindings; fake
callback с именем/метаданными state.read не становится таким binding через
рекурсивный composite. Pure profile не получает state permission. Разрешения
транзакционного UI и поведение ошибок остаются прежними.

## Вызов, состояние и пределы

Каждый вызов получает новый frame и собственные локальные Variable/storage.
Результат возвращается caller, который продолжает свою activation sequence.
Persistent UI state общее в пределах транзакции события. Ошибка в caller после
рекурсивных записей и превышение depth откатывают все записи этого события.

Прямые, взаимные и entry↔helper вызовы выполняются Runtime/standalone одинаково.
Используются существующие `CALL_DEPTH` и `STEP_LIMIT`, без сброса work ledger
при входе в новый frame. Одинаковый бюджет300 позволяет завершить один уровень
тестового счётчика, но отказывает на пяти уровнях; каждый отдельный frame имеет
тот же короткий код. Бесконечная рекурсия завершается контролируемой ошибкой,
не успехом с произвольным значением и не host RangeError. Оптимизация tail calls
не заявляется. Общее доказательство завершения статически не выполняется.

Прежние ограничения1024 нод,256 на граф,32 определения и1MiB сохраняются.
Пределы runtime определяет вызывающая среда; поля документа не повышают бюджет
или глубину. Source и его flow lowering могут расходовать разное число IR steps
из-за dispatcher-кода, поэтому одинаковое поведение при произвольном малом
численном budget между разными lowering не обещается. Runtime/standalone одного
flow IR проверяются на одинаковые значения и коды ошибок.

## Редактор и диаграммы

В каталоге доступны self, entry и взаимные вызовы как обычные контракты.
Перетаскивание не соединяет их автоматически. «Открыть контракт» открывает
соответствующее определение, а не копию или бесконечное дерево. При открытии
entry из helper сохраняется Back breadcrumb; можно вернуться к helper и далее
в исходный root. Индивидуальные canvas/view/описания остаются на месте.

SVG содержит конечный набор компонентов определений и call-блоки, включая
рекурсивные ссылки. Runtime trace различает определения; полноценный редактор
stack frames и debugger stepping остаются отдельной работой.

## Проверяемые примеры

[recursive-flow.ems](../../examples/recursive-flow.ems) и
[проект](../../examples/recursive-flow.ems-project.json) демонстрируют факториал
для неотрицательных целых n в пределах execution limits; вектор n=5 →120.
Это не новый тип Int или полный математический контракт для всех Number.
CLI flow-run/build/svg принимают /3. Independent JS выполняется без EMS.

Node tests: entry self recursion, mutual parity, entry/helper cycle, isolated
mutable frames, recursive arrays, shared budget/depth, profile/version refusal,
source preservation, import/export и конечные diagrams. UI: mutual policy,
source/IR/flow witnesses, shared events6→12, rollback по DIV_BY_ZERO/CALL_DEPTH,
fake state binding refusal. Chromium: Worker120→graph edit240/reopen240/JS240;
actual self-call drag и bounded failure; UI3→6/reopen6 и rollback0;
entry→helper→entry→Back без потери navigation context.

Полная двусторонняя проекция текста, broader source profiles, контрактные
instances/invariants, Map и межфайловые imports остаются открытыми. Глобальная
цель EMS этим срезом не завершается.
