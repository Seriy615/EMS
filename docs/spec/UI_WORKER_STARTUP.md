# Запуск UI Worker — AC-135

Связь с целью: G-11/G-14. Это жизненный цикл хостового транспорта;
семантика контрактов, IR, разрешения и транзакции UI не меняются.

## Наблюдаемая причина

Раньше клиент отправлял `init` сразу после создания Worker. Один `initTimeout`
охватывал загрузку HTTP-модуля, его транзитивные imports и выполнение инициализации
EMS. Контролируемый настоящий Node Worker с задержкой загрузки 800 ms и
`initTimeout: 500` завершался `EXECUTION_TIMEOUT` ещё до установки host handler.
Это доказывает смешение бюджетов, но не объясняет все прежние Chromium startup,
CDP/Page.load и сетевые сбои.

## Протокол и бюджеты

`/web/ui-worker.mjs` устанавливает обработчик сообщений после загрузки зависимостей,
затем отправляет ровно `{type: 'ready', protocol: 'ems-ui-worker/1'}`.
Это только готовность транспорта: пользовательская программа ещё не передана,
её корректность и успешная инициализация не утверждаются.

`createUIWorkerRuntime` по умолчанию ждёт этот сигнал от встроенного browser Worker.
До него проект не передаётся и EMS не исполняется. Неверный формат/версия,
лишние поля и повторный ready закрывают транспорт; автоматического обхода нет.
Обычный `init` по-прежнему проверяет документ, типы, capabilities и начальное
состояние, и только подтверждённый snapshot открывает runtime вызывающему коду.

- `loadTimeout`: ожидание загрузки, по умолчанию 5000 ms, допустимо 1..60000.
  Истечение даёт `UI_WORKER_LOAD_TIMEOUT`, `details.phase: 'loading'` и сообщение
  по-русски. Worker завершается без отправки проекта.
- `initTimeout`: 5000 ms, прежний лимит **выполнения инициализации**, начинается
  после ready. `EXECUTION_TIMEOUT`, `phase: 'initialization'`.
- `timeout`: прежние 5000 ms на запрос события (в debug явно 60000), с момента
  постановки запроса, включая очередь/паузу. `EXECUTION_TIMEOUT`, `phase: 'execution'`.
  Загрузка не увеличивает время, отпущенное вычислению события.

По умолчанию суммарное ожидание загрузки транспорта и его init теперь ограничено **5000 + 5000 ms**,
а не прежними 5000 ms на загрузку и инициализацию вместе. Синхронная проверка debug-профиля и вызов factory предшествуют этим таймерам. Таймеры — host deadlines,
не гарантия жёсткого real-time при остановленном JS event loop.

Для внедрённых `workerFactory` прежний транспорт без ready сохраняется:
`waitForReady` по умолчанию false. Современный адаптер явно задаёт
`waitForReady: true` и реализует тот же протокол. Это выбор API, а не fallback
после таймаута. `loadTimeout` в старом режиме не используется, init начинается сразу.

## Отмена

Необязательный `signal` охватывает весь срок жизни preview, включая загрузку,
инициализацию и события. Заранее отменённый сигнал не создаёт Worker. Отмена,
ошибка и close очищают timers/listeners, прекращают незавершённые запросы и
завершают Worker; поздние ответы не меняют последний подтверждённый snapshot.
Сигнал отдельного `dispatch` сохраняет прежние правила отмены сессии.

Native UI передаёт отдельный AbortController каждому запуску. Повторный запуск,
Stop и pagehide отменяют предыдущий, включая ещё не вернувшийся runtime.
Обработчик pagehide установлен до первого await старта. Revision не позволяет
устаревшему запуску монтировать DOM или показывать ошибку вместо нового.
Legacy UI получает readiness через тот же стандартный browser client; отдельное
управление отменой незавершённого legacy startup в этом срезе не добавлено.

## Проверка и границы

Node: `tests/ui-worker-startup.test.mjs`, `tests/ui-worker.test.mjs` — разделённые
бюджеты, строгий протокол, запрет передачи до ready, отмена, malformed data,
ошибки политики до создания Worker, явный старый транспорт, настоящий Worker
с задержкой загрузки и настоящими UI-событиями. Существующий infinite-handler
тест сохраняет ограничение исполнения и последний подтверждённый snapshot.

Chromium: `tests/browser/ui-worker-startup.test.mjs` — proxy задерживает настоящий
HTTP Worker module, стандартный browser factory проходит загрузку дольше короткого
init-бюджета и исполняет реальный обработчик; native Stop/restart не монтирует
отменённый запуск. Другие regression gates фиксируются в STATUS/PROGRESS.

Это не retry, не исправление запуска процесса Chromium/CDP, не доказательство
отсутствия сетевых ошибок и не обещание стабильности любого холодного браузера.
Standalone использует прежний runtime/compiler без этого IDE Worker транспорта.
