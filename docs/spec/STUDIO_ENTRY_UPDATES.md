# Вход в Studio и проверяемая версия PWA — AC-118

Главный адрес `/` открывает проекты. Закладки `/?project=…` и workspace file
выбирают редактор по проверенному kind документа: flow, UI, workspace или
прежний graph/source. Перенаправление не меняет документы/черновики. Явный
`/web/index.html` сохраняет доступ к reference source editor; ранее сохранённые
локальные проекты доступны ссылкой на главной. Неподдерживаемый/неизвестный
проект показывает ошибку, не заменяет его пустым проектом. Это маршрутизация,
а не завершённая миграция standalone source в новый flow.

На главной показан идентификатор загруженной сборки и кнопка «Проверить
обновление». Generated build-id входит в тот же offline cache, что и приложение;
поэтому старая открытая PWA показывает свой идентификатор, не номер последнего
ответа сервера. Build generator создаёт build-id и manifest из одного hash всех
app assets, worker и самого генератора; generated build-id исключён из своего
содержимого hash во избежание цикла. Node gate проверяет оба generated файла.

Read-only `GET /api/release` возвращает `{schemaVersion:"ems-release/1",
release:<40-hex-or-null>, assets:<24-hex>}`. На VPS release — имя фактического
каталога запущенного артефакта, локально null. No-store; endpoint не читает Git,
credentials, каталог пользовательских программ и не принимает записи. Это
операционная идентификация сборки, не подпись пакета и не security attestation.

Новое приложение сохраняет cache-first связность модулей. Waiting worker не
активируется сам во время редактирования. Уведомление просит сохранить изменения
во всех вкладках. По явному «Обновить» приложение сверяет waiting worker через
MessageChannel с текущим API assets; несовпавший/устаревший worker не активируется.
После активации перезагружается вкладка, в которой нажата кнопка. Другие вкладки
сохраняют свои поля до явного обновления; если controller уже обновлён из другой
вкладки, их кнопка выполняет обычный reload после проверки версии. Активация общей
service-worker scope меняет controller всех вкладок; сохранение во всех вкладках
до обновления обязательно для несохранённых полей формы.

Закрытие уведомления не перезагружает страницу. Ошибка сети не уничтожает offline
cache и проекты. Проверки выполняются по кнопке и стандартному registration
update, без частого polling/history mutation. Старое сообщение `{type:"activate"}`
сохранено для обновления уже установленных предыдущих PWA.

Приёмка: реальный root/bookmark routing без изменения байтов хранилища; real SW
A→B, ожидание подтверждения, отказ stale waiting build, сохранение графа,
обновление второй вкладки её кнопкой, offline reload; public API соответствует
развёрнутому Git release и build-id открытой главной. Прежние editor scenarios
используют явный reference URL, самостоятельные приложения остаются на своём
корне и не запрашивают `/web/` или `/src/`.
